# 数据口径验证方法（连库取数的防坑清单）

> 定位：**跨 Agent / 跨系统复用**的查询知识（L1 行业知识）——任何「从业务库只读取数 → 沉淀口径 → 出报表」的工作（sMES/LIMS/U9/玖坤等）都适用。
> 来源：2026-08-14 报工口径二轮审计实战提炼（分次续报/同量合并/跨天污染/RESCLASS/进行中判据，见 [`changelogs/chongqing-smes-report.md`](../changelogs/chongqing-smes-report.md) 相关提交与 `smes-621-sql/厂区报工报表规范.md`）。
> 用途：写查询模板、验证口径、做数据审计时对照本清单，避免重复踩坑。

## 一、验证姿态（怎么做审计才叫严谨）

1. **证伪式验证**：对每条沉淀口径，不只「跑通了」就算对，要主动问「什么情况下这条口径会错？」并构造对应查询去验证。
2. **覆盖数据形态的多样性**：当前样本里没有 ≠ 未来没有。逻辑缺陷（哪怕当前未触发）照样要修，否则就是埋在报表里的定时炸弹。
3. **结论必须带适用条件**：凡是「实测验证过」的结论，都要写明「在什么条件下成立」——样本范围变了，结论要能对照重跑复验。
4. **验证结果可复验**：留验证日期、验证用的 SQL/样本范围、当时的判定；将来数据形态变化时可重新验证对比。

## 二、四大高频坑

### 坑1：DISTINCT 合并漏算 —— 聚合必须用 GROUP BY + SUM

- **场景**：明细表同一逻辑组有多行（如同一报工组一天分两次进出站），想按组求和。
- **错法**：`SELECT DISTINCT 组, 量 ...` 之后在外层 `SUM(量)` —— 同组两次**量恰好相同**时，DISTINCT 把两行合并成一行，**漏算**（静默错误，不报错）。
- **对法**：子查询先 `GROUP BY 组, SUM(量)` 聚合成组总量，外层再 SUM。
- **判据**：凡「同组多行、想按组聚合求和」→ 永远 GROUP BY 聚合；`DISTINCT(组,量)` 只在量互不相同的当前数据上碰巧可用，**防御不了未来数据**。
- **实例**：报工 ⑤/⑥ 原 `DISTINCT LOGGROUPSERIAL, InputQty` → 改 `GROUP BY LOGGROUPSERIAL, SUM(InputQty)`。

### 坑2：JOIN 侧时间维度未过滤 —— 跨期污染

- **场景**：主表按「当日」过滤，但 JOIN 的辅助表（人员/资源/历史记录）没按时间过滤。
- **错法**：`WHERE 主表.日期 = 当日 JOIN 辅助表`（辅助表不带时间条件）→ 跨天/跨期组的历史成员、历史量被带入当日。
- **对法**：**每一侧**都按同一口径过滤时间：辅助表子查询里也加 `WHERE 辅助表.时间 = '当日' OR '' = ''`（date 可空约定）。
- **判据**：「当日视角」的查询，每个 JOIN 子查询的时间字段都要过滤，不只主表。
- **实例**：报工 Resource 成员表原来不按 EVENTTIME 过滤，跨天报工组会把历史成员带入今日。

### 坑3：同名/近名字段语义混淆 —— 字段语义以实测为准

- **场景**：两张表都有 `ENDTIME`（如设备出站时间 vs 报工结束时间，**语义可相反**）；某字段取值被想当然解读（如 RESCLASS 0/1/4 被读成「1=设备」）。
- **错法**：从列名和取值猜语义、直接拿来过滤或统计。
- **对法**：跨表取字段前先**实测确认语义**（跑分布、看关联主数据、对业务含义）；同名近似字段逐一确认「这个字段在这张表里到底什么意思」。
- **判据**：字段语义只能从数据/字典实测得出，不能凭列名推断；取值含义尤其要防「看着像枚举就猜」。
- **实例**：进行中判据必须用 `报工结束时间 IS NULL`（设备可能已出站但报工未闭环）；RESCLASS 0/1/4 实测全为人员工号。

### 坑4：验证结论过度泛化 —— 单形态样本 ≠ 无条件断言

- **场景**：在某种数据形态上验证通过（如当日无分次续报 →「两表逐条一致」），沉淀成**无条件**的普适结论；另一厂区出现分次续报后，单行对比不再成立。
- **错法**：写「两表逐条核对完全一致，取哪个都行」——样本没覆盖到分次续报形态。
- **对法**：结论写明**适用前提与样本范围**（如「仅对无分次续报组成立；分次续报组单行不等、组 SUM 一致」），表达成「前提 + 结论」而非无条件断言。
- **判据**：凡是跨场景通用的话术，必须能找到它成立的边界条件；找不到 → 先标注「当前样本下成立」。

## 三、行为铁律

> **口径即资产，验证即留痕**。每条沉淀口径都带：验证日期 + 样本范围 + 适用前提。模板/口径卡/规范/报表四处同步（改一处必改四处），验证结论修改时同步更新适用条件，不做「此刻成立就永久成立」的隐含假设。
