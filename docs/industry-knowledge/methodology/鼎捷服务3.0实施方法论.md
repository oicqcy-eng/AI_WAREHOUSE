# 鼎捷服务 3.0 实施方法论（M1–M5）

> **定位**：制造业 ERP/MES 系统实施全过程管理方法论，跨项目可复用。
> **来源**：鼎捷数智《华纬sMES项目管理共识纪要 v1.0》（2025-06-13）+《机制流程规划/生产任务透明管理规划报告》，经提炼脱敏。原件见 `delivery/projects/hw-spring-mes/input/project/raw/`。
> **沉淀日期**：2026-08-13

## 一、实施阶段框架（服务 3.0 V4.0）

| 阶段 | 名称 | 核心工作 | 阶段交付物 |
|------|------|---------|-----------|
| M1 | 项目启动 | 项目组人选最终确立、确认工作计划、召开高层启动会、里程碑分解月度项目日历 | 《项目管理共识纪要》《系统安装报告》 |
| M2 | 机制流程规划 | 现状调研→规划《生产任务透明管理规划报告》→开机制流程规划报告会→**设置模拟检核脚本**（系统功能/工作流/消息通知/界面/打印格式多维检核） | 《生产任务透明管理规划报告》《机制流程规划报告》《需求差异分析书（二开规格）》 |
| M3 | 流程和数据验证 | 核心流程+作业流程培训（SOP 范围）；逐项测试并**实施顾问签字确认**；判定上线可行性 | 《流程和数据验证暨上线可行性报告》《用户操作手册》（关键用户编写） |
| M4 | 实施运行 | 上线前条件确认+上线动员、上线检讨会（结合问题管制表）、首月现场支持、**上线周检讨机制** | 《首月运行报告》 |
| M5 | 运行成果总结 | 指标产出原因分析（规划不足 vs 执行不力）→改善行动计划、运行成果总结大会 | 《运行成果总结报告》 |

**交付审核程序**：所有交付文档经客户方项目经理审核，**文档提交之日起 3 个工作日内完成**；重大决定由项目领导小组批准。

## 二、实施策略（原则）

1. **目标明确、结果导向**：先按标准操作流程固化操作模式推动上线，再依瓶颈问题优化改进
2. **模拟试运行重点投入**：积累经验、确保效益；用模拟数据进行系统测试
3. **培训培训者（TTT）+ 最终用户早参与**：先培训关键用户，最终用户尽早参与；培训考核结果与个人利益关联
4. **数据准备与测试贯穿每个阶段**：数据的及时、完备、准确决定上线成败（静态+动态数据都需最终用户认可正确性）
5. **关键用户提前参与**：测试情景由最终用户部门参与编写认可，保证测试完整性
6. **严格控制范围变更**：所有可能延长工期/增加成本的范围问题由项目指导委员会决策

## 三、关键工作项分工（客户 vs 实施方）

| 工作项 | 客户方责任 | 实施方责任 |
|--------|-----------|-----------|
| 基础资料收集整理录入 | 学习录入操作、确认**四大主基础资料**（物料/设备/人员/检验资料）基准笔数、**上线前 1 个月**完成进度计划 | 培训收集/检核/录入操作、帮助前期批量导入 |
| 技术类自定义工具 | 学习自定义设置工具、上线前完成设置调整 | 培训：权限分配/流转卡格式设计/报表数据源修改/自定义报表设计（完成判定=可独立完成一笔完整调整） |
| 系统应用培训 | 参训、制作岗位操作手册、依计划组织培训 | 操作培训、指导岗位手册编写方法、定期检视培训执行 |
| 期初工单规划 | 确认期初工单数据量、指派负责人员、按期完成并由实施方稽核 | 指导盘点/录入进度安排、稽核导入结果 |
| 系统上线运行 | 执行上线周检讨、单据及时准确完整、保证月结标准、网络硬件正常 | 前 2 周+首月**现场支持**（后转在线）、每周上线周检讨会、产出《问题管控表》、督促日清日结、协助运维能力建设 |

## 四、项目管理制度

### 会议制度
- **月度例会**：每月 26 号，高层+双方项目经理，解决重大事项（会前 2-3 天准备、会前 2 天书面通知）
- **项目组例会**：每两周，线下+远程，审核过去两周完成情况、确认后续计划
- **临时会议**：突发事件即时商榷
- **阶段性项目汇报会**：每阶段结束向领导汇报（调研/透明化管理交付物/蓝图报告/模拟上线/设备整合接口/验收报告）

### 沟通与文件制度
- **周计划**：顾问周五前发下周辅导通知单；客户方项目经理周日 18:00 前确认
- **文件命名**：`项目名称+文件名_版本号_日期`（版本号小写 v+一位小数；日期 YYMMDD），如 `【华纬科技 sMES】_项目管理共识纪要 v1.0_20240920`；注意版本控制
- **文件存档**：过程文档备份服务器；最终文档（签字确认版）双方各存一份

### 问题报告与解决
- 问题记录由实施方顾问集中更新维护、负责跟踪，**双周会汇总**；关键控制点出具《项目风险管理清册》
- 上线问题记录于《问题管控表》，定期检核复盘

### 范围变更管理
变更申请书 → 审批 → 影响分析（变更申请分析报告）→ 项目决策委员会/领导小组审批 → 正式记录通知 → 关闭记录。四阶段：记录/审批/分析/申请。

### 风险管理（常见 5 类 + 应对）
| 风险 | 应对 |
|------|------|
| 一把手作用流于表面 | 高层提高投入时间深度、建立严格项目决策机制、高层及时部门协调 |
| 缺乏骨干资源 | 配备足够人员+各部门业务骨干、建立项目人员绩效考核 |
| 迁就现状不能统一流程 | 业务流程标准化规范化、高层坚定支持 |
| 培训与思想引导不足 | 有效培训沟通、及时组织多层次培训、宣传/激励/听取反馈 |
| 数据收集整理不及时 | 及早确定导入数据范围与办法、指派专人收集清理基础数据 |

### 交付品验收与质量保证
- 验收：阶段报告→领导小组会议→意见→修改→最终报告→**3 个工作日内项目经理签字验收**
- 质量监控两类：**文件交付品**（模板/架构/进度监控/审阅/签署）与**定制化开发**（关键用户签字确认《客户需求书》后再开发）

### 知识转移（四层次）
项目经理→项目管理层；规划顾问→关键用户/内部顾问；实施顾问→IT 部门/关键用户；关键用户/内部顾问→其他员工。
方式：项目管理原则培训（建立共同语言）+ 系统应用操作培训 + 协助最终用户内训（TTT）。

## 五、与本项目厂区实施的关系

- 华纬集团各公司 MES 为**同一体系（鼎捷 sMES）分厂区/分期推进**：稳定杆项目（2024.09-2025.09，一期）→ 三厂小簧/一厂大簧/重庆等扩展
- 上述 M1-M5 框架、交付物与制度可直接作为三厂小簧等厂区实施阶段对照的**标准基线**
- 稳定杆项目的生产透明/质量/设备/ERP 交互规划细节见 `input/project/raw/` 原件（脱敏后供参考）
