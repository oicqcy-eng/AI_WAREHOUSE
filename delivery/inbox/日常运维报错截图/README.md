# 日常运维报错截图

> **用途**：把生产系统（sMES/LIMS/U9/玖坤 等）运行时的报错截图直接扔进这个文件夹。Claude 会读取截图、结合连库与既有资产排查根因，并把每类报错沉淀成「排障卡」进运维知识库 `delivery/projects/hw-spring-mes/ops-knowledge/`，后续同类报错可秒答。

## 怎么用

1. 报错时**把整条报错完整截下来**（含错误码/报错窗口/出错页面 URL 或功能名/时间），**别只截半条**——错误码常折叠在详情里
2. 复制进这个文件夹（原图保留在别处无妨）
3. 文件名建议：`YYYY-MM-DD_<厂区>_<系统>_<报错简述>.png`（如 `2026-08-15_一厂大簧_sMES_保存报工超时.png`）
4. 在对话框说一声「**处理运维报错截图**」（或类似的话）
5. Claude 会：
   - 读图 → 提取报错特征（错误码/报错模块/触发场景/时间）
   - 结合资产排查根因（连库验证 / 查数据字典 / 翻历史记录），是系统 bug、配置问题、数据异常还是操作问题
   - 沉淀成**排障卡**进 `delivery/projects/hw-spring-mes/ops-knowledge/`，并在 worklog 建任务跟踪
   - 汇报：这张图的报错是什么、根因、你该怎么处理
6. 处理完成后截图可移走或删除，保持文件夹**接近清空**

## 规则

- **顺手补一句上下文**：当时在做什么操作（"报工时点保存报的" vs "打开看板报的"）——这是最能定位问题的线索，截图本身给不出
- **截图直接扔，不用脱敏**：本文件夹的报错截图被 `.gitignore` 忽略，不入 git，仅本地
- **重复报错也扔**：同类报错第 2 次出现直接贴图，我会匹配已有排障卡确认是否同根因、是否复发
- **排障卡沉淀到 `ops-knowledge/`**：每类报错一张卡（症状/根因/排查步骤/已排除项），跨厂区共库的放项目根级，厂区专属的按厂区分子目录
- **支持的文件**：截图 `.png` `.jpg`，以及带报错文字内容的 `.txt`/`.md`（报错弹窗能复制文字时贴文字最快）
