# 重庆查询报表规范（2026-08-14 定版）

> 重庆 sMES 报工数据「查询 → 报表」的工作流规范。核心认知：**模板（口径）是资产，报表是「可重跑的视图」**。
> 任何一张报表 = 模板 + 日期 + 跑一次，随时可重新生成——所以不必过度维护报表文件，重点维护模板与口径。

## 一、分层与文件定位

| 层 | 文件 | 定位 | 维护策略 |
|----|------|------|---------|
| 模板（权威） | `sql/重庆报工查询-SQL.sql` | 口径唯一固化处，6 视角可重跑 | 改口径必记变更日志（见三） |
| 运行版（交付） | `output/c_q_mes/重庆报工查询-SSMS运行版.sql` | 给用户/现场用 SSMS 直接跑 | 与模板同源，模板改后必须同步 |
| 报表（快照） | `output/c_q_mes/YYYY-MM-DD_重庆报工数据报表.md`(+docx) | 当日数据视图，可随时重跑再生 | 见二覆盖规则 |

## 二、报表覆盖规则

- **按日命名**：`YYYY-MM-DD_重庆报工数据报表.md`，跨天不覆盖（每天独立文件）
- **当天内可覆盖**：当天多次导出以最后一份为准；历史版本靠 **git 留痕**回溯
  （`git log -- <报表路径>` 可看每次改动的提交）
- 报表是廉价可重跑视图，被覆盖不心疼——数据源头在库，模板可随时重跑同口径

## 三、模板变更流程（铁律）

改 `重庆报工查询-SQL.sql` 时，**一次改四处**：

1. **模板变更日志**：在模板头部「口径变更日志」节记一行（日期 + 改了啥 + 是否口径变更）
2. **SSMS 运行版**：`重庆报工查询-SSMS运行版.sql` 同步同口径（占位符 {{date}} ↔ @date 转换）
3. **知识卡速查**：`knowledge/设备口径卡.md` 相关口径节更新
4. **报表口径注意**：报表头部元数据「口径版本」+ 尾部「口径与注意」更新

> 口径在三处各有呈现目的（模板=技术细节、知识卡=速查、报表=解读），**各写各的但必须一起改**，不建第四份"字典"文件。

## 四、报表生成规范

每次生成报表，头部带 3 行元数据（自描述，一年后打开也能追溯）：
```
> **生成时间**：<日期>（当天多次导出以最后一份为准，git 留痕可回溯）
> **数据截止**：<日期> 24:00（含进行中报工 N 次，ENDTIME 为空）
> **口径版本**：V2（<关键口径一句话>）
```

**报表板块结构（7 节清单，2026-08-16 用户决策替代"必出"）**：以下 7 节是**完整配置（全套）**，但**每次生成报表前必须先向用户展示 7 节清单并询问需要哪几节**，按用户选择输出，**不再默认全 7 节强制必出**——用户明确「不是每次都需要累计总览、按天分布等」。可用编号回复（如"1,3,5,7"）或选组合：

1. **元数据头**（3 行）
2. **一、累计总览**：记录数/设备数/生产批数/工单数/投入/产出/产出率/时间跨度
3. **二、按天分布**：全量按日报工（近 14 天明细 + 阶段特征）
4. **三、今日报工明细**：设备×生产批×作业站逐条，✅已完成 / 🔄进行中
5. **四、按报工人员统计**：**列集固定 7 列** `工号/姓名/报工次数/生产批/工单/投入/产出`（= SQL ⑥ 视角原样，含 DS 系统代报）——**含产出、工单，任何版式不得裁剪**（2026-08-18 纠正：曾漏产出列）
6. **五、按工单累计汇总**：工单/产品/设备数/投入/产出
7. **六、观察与备注**：产出率缺口/设备接入率/人员口径陷阱/待确认项

> **常用组合速查**：全套 = 1-7；快看版（日常跟线）= 今日总览+今日明细+观察；累计版（阶段/月度汇报）= 累计总览+按天分布+按工单汇总+观察。
> **板块列集铁律（2026-08-18 定）**：**含某板块就要带它的全部标准列**——尤其 ④人员统计 7 列、③明细 的「投入/产出/时间/状态」、①累计 的「产出率」等；任何版式裁剪只减**板块**不减**列**。**③今日明细 无论逐条还是按「设备×工序」聚合，均须同时带「投入+产出」并注明状态**（8-17 曾只带投入被纠正）。生成时以「本节清单 + 最近一份完整报表」为版式基准，不得自由发挥。
> **输出方式（2026-08-16 用户决策）**：确认板块后直接生成 Word（docx）交付，不在对话内贴全量报表内容——对话只给结果摘要与文件路径，明细进 docx。
> **取数 limit 约定（2026-08-16 用户决策）**：跑数据源查询时按需带足 `--limit`，遇到截断提示就调大——limit 只截显示/导出、不控拉取量，调大纯收益无内存风险。参考：今日明细/人员 ~500；按天/工单 ~200；全量历史导出 ≥6000。query-mes.js 默认已 1000。
> 历史：8-14 报表 7 节齐全 ✅；8-15 曾定"7 节必出、不得裁剪"并补齐首版 5 节偏差；8-16 用户改为"先问再选"——**规则以用户最新决策为准**。

## 五、关键口径速查（V3，2026-08-14）

| 口径 | 定义 |
|------|------|
| 本次投入/产出 | `TBLWIPCONT_EQUIPMENT.InputQty/OutputQty` = `TBLWIPLOTLOG_REPORT.INPUTQTY/GOODQTY+FAILQTY`（两表逐条核对一致**仅对无分次续报组成立**——重庆当日 19 条全等无此组；分次续报组 E 单行≠L 单行、组 SUM 一致，见一厂口径卡；**resource.INPUTQTY 是资源加工量，勿用于投入统计**） |
| 报工人员 | `TBLWIPCont_Resource.USERNO`（设备表 Creator 为空），姓名映射 `TBLUSRUSERBASIS` |
| 进行中报工 | `TBLWIPLOTLOG_REPORT.ENDTIME IS NULL`，投入为当前累计 |
| 多人协作 | 同 LOGGROUPSERIAL 多 USERNO，按人各计一次，人员口径总和 ≠ 报工日志总量 |
| 系统代报 | `USERNO='DS'` = 系统管理员代报（用户确认 2026-08-14），看纯车间报工可排除 |
