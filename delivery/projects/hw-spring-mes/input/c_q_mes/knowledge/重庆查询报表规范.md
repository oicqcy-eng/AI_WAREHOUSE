# 重庆查询报表规范（2026-08-14 定版）

> 重庆 sMES 报工数据「查询 → 报表」的工作流规范。核心认知：**模板（口径）是资产，报表是「可重跑的视图」**。
> 任何一张报表 = 模板 + 日期 + 跑一次，随时可重新生成——所以不必过度维护报表文件，重点维护模板与口径。

## 一、分层与文件定位

| 层 | 文件 | 定位 | 维护策略 |
|----|------|------|---------|
| 模板（权威） | `sql/重庆报工查询-SQL.sql` | 口径唯一固化处，6 视角可重跑 | 改口径必记变更日志（见三） |
| 运行版（交付） | `output/c_q_mes/重庆报工查询-SSMS运行版.sql` | 给用户/现场用 SSMS 直接跑 | 与模板同源，模板改后必须同步 |
| 报表（快照） | `output/c_q_mes/YYYY-MM-DD_重庆报工数据报表.md`(+docx) | 当日数据视图，可随时重跑再生 | 见二覆盖规则 |

## 二、报表覆盖规则

- **按日命名**：`YYYY-MM-DD_重庆报工数据报表.md`，跨天不覆盖（每天独立文件）
- **当天内可覆盖**：当天多次导出以最后一份为准；历史版本靠 **git 留痕**回溯
  （`git log -- <报表路径>` 可看每次改动的提交）
- 报表是廉价可重跑视图，被覆盖不心疼——数据源头在库，模板可随时重跑同口径

## 三、模板变更流程（铁律）

改 `重庆报工查询-SQL.sql` 时，**一次改四处**：

1. **模板变更日志**：在模板头部「口径变更日志」节记一行（日期 + 改了啥 + 是否口径变更）
2. **SSMS 运行版**：`重庆报工查询-SSMS运行版.sql` 同步同口径（占位符 {{date}} ↔ @date 转换）
3. **知识卡速查**：`knowledge/设备口径卡.md` 相关口径节更新
4. **报表口径注意**：报表头部元数据「口径版本」+ 尾部「口径与注意」更新

> 口径在三处各有呈现目的（模板=技术细节、知识卡=速查、报表=解读），**各写各的但必须一起改**，不建第四份"字典"文件。

## 四、报表生成规范

每次生成报表，头部带 3 行元数据（自描述，一年后打开也能追溯）：
```
> **生成时间**：<日期>（当天多次导出以最后一份为准，git 留痕可回溯）
> **数据截止**：<日期> 24:00（含进行中报工 N 次，ENDTIME 为空）
> **口径版本**：V2（<关键口径一句话>）
```

## 五、关键口径速查（V2，2026-08-14）

| 口径 | 定义 |
|------|------|
| 本次投入/产出 | `TBLWIPLOTLOG_REPORT.INPUTQTY / GOODQTY+FAILQTY`（equipment 的 InputQty/OutputQty 为生产批累计，勿当单次量） |
| 报工人员 | `TBLWIPCont_Resource.USERNO`（设备表 Creator 为空），姓名映射 `TBLUSRUSERBASIS` |
| 进行中报工 | `TBLWIPLOTLOG_REPORT.ENDTIME IS NULL`，投入为当前累计 |
| 多人协作 | 同 LOGGROUPSERIAL 多 USERNO，按人各计一次，人员口径总和 ≠ 报工日志总量 |
| 系统代报 | `USERNO='DS'` = 系统管理员代报（用户确认 2026-08-14），看纯车间报工可排除 |
