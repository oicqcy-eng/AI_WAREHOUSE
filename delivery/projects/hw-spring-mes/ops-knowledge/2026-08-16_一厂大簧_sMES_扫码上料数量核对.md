# 排障卡：扫码上料条码存在但「上料数量/绑定」对不上

> **系统**：sMES（共库 Home）｜ **厂区**：一厂大簧（表为 sMES 通用表，各厂适用）｜ **功能**：首站扫码上料数量核对 ｜ **首次记录**：2026-08-16
> **来源**：用户投喂 4 张 SSMS 排查截图（inbox）+ 连库实测验证（MO1012606290117 / MO1012601190039）

## 症状

- 与「条码不存在 MES」（见 8-15 排障卡）不同的另一类：**条码已在 MES 有上料记录，但上料数量与需求/应上料数量不一致**（InputQty ≠ Qty）
- 现场表现：扫码上料后校验工单×原料×批次绑定时数量对不上，或需排查某工单到底上了多少料

## 关键表（8-16 连库实测确认）

| 表 | 角色 | 关键字段 |
|----|------|---------|
| `Tbloemomateriallist` | U9 发料侧（需求/已领/缺料） | REQUIREQTY=U9需求、ORGMATERIALQTY=已领、STDQTY=标准用量(KG/PCS)、SUBSTITUTEMATERIALNO=原料条码 |
| `TBLWIPEQPMATERIALSTATE`（17列） | **扫码上料执行状态** | InputMaterialNo=扫码原料、MaterialLotNo=原料批次、**InputQty=已上料**、**Qty=需求/应上料**、EquipmentNo=设备、OPNo=LOTCREATE(生产批开立/首站) |
| `TBLWIPCONT_MATERIAL` | 报工消耗物料 | **LOGGROUPSERIAL 前缀=生产批号**（LOTSERIAL 是原料批次序列号，勿当生产批用）、USEQTY=报工消耗量 |

## 排查步骤（三视角，统一模板 `data/smes-621-sql/发料查询-SQL.sql`）

```
node agent/mes-implement-expert/tools/query-mes.js data/smes-621-sql/发料查询-SQL.sql --profile home -p mono=<工单> --show 1|2|3
```

1. **①发料核对**（--show 1）：U9 需求 REQUIREQTY / 已领 ORGMATERIALQTY / 缺料。需求>0 已领=0 → 未发料（对应"条码不存在"）
2. **②扫码上料状态**（--show 2，核心新增）：按设备看已上料 vs 需求。`(InputQty-Qty)≠0` 即数量对不上——实测 MO1012606290117 一条原料批次 S2606174 分配 6 台设备，差异最大 BJ02（上料 10520 vs 需求 520，差 10000）
3. **③报工进站核对**（--show 3）：实际进站消耗（SUM(USEQTY)）vs U9 需求/已领。实测 MO1012601190039 需求 19500/已领 0，报工消耗仅 3.9 → 上料未执行

## 判读闭环

- ①需求>0 已领=0 → 未发料/未同步（条码不存在）→ 查 U9 发料单
- ②上料差异≠0 → 上料数量输错/分次未到位 → 核对设备上料记录
- ③消耗量<<需求 → 报工未实际扣料 → 查报工流程/绑定关系

## ⚠️ 坑

- `TBLWIPEQPMATERIALSTATE.CreateDate` 实测多为 NULL，时间线看 `ReviseDate`
- 一条原料批次按设备**各一行**（同批分给多台设备），勿用 COUNT 当批次数
- `TBLWIPCONT_MATERIAL.LOTSERIAL` 是原料批次序列号，**不是**生产批号；按工单过滤用 `LOGGROUPSERIAL LIKE 生产批+'%'`
- 工单号注意位错：用户界面 `MO01012608050056`（16位）vs 库中 `MO1012608050056`（15位），先模糊 LIKE 确认
