# 排障卡：H5端派工调度中心页面空白/无作业按钮

> **系统**：sMES（共库 Home）｜ **厂区**：三厂小簧（表为 sMES 通用表，各厂适用）｜ **功能**：H5 端派工调度中心作业群组权限 ｜ **首次记录**：2026-08-21
> **来源**：用户投喂截图（inbox/派工调度中心_2026-08-21_16-12-02.jpg）+ 连库实测验证（HW0403 / SCXH-PLN001）

## 症状

- 用户能登录、左侧菜单能进「派工调度中心」、页面标题与「前置作业」页签正常显示
- **但页签下所有作业按钮全空白**（生产批开立/派工作业等一个都不显示）
- 用户反馈"作业群组权限都设置好了，还是没有派工权限"

## 关键判断：菜单权限编号（H5） vs 平台权限编号 + H5 加载 三层

**第一层（PRIVTYPE 区分两套编号，本次对照 XH02/CL01 实测确认）**：
- `PRIVTYPE=9` = **菜单权限编号**（A07 派工作业/A01 派工设定/B0101 生产批开立…）→ **H5 端「派工调度中心」等模块按钮显示的关键**
- `PRIVTYPE=0` = **平台权限编号**（DISPATCH OPERATION/LOT CREATE 等英文编号）→ 在线报工平台侧控制，**H5 端不认**
- `PRIVTYPE=8` = 按钮级 CRUD（Add/Edit/Delete/View/Export…）

**根因（2026-08-21 对照 HW0396/CL01/XH02 定版）**：SCXH-PLN001 群组里**只配了平台权限编号（PRIVTYPE=0）**（DISPATCH OPERATION/A03/A10/APS…看似齐全），**缺 A 系列菜单权限编号（PRIVTYPE=9）**（A07 派工作业/A01/A03/A05/A06/A08/A10/A0401/A0402/E05 全缺）→ H5 端「派工调度中心」模块整体不渲染 → 页面空白。**不是刷新问题，是权限编号维度配错了。**

**对照案例（决定性证据）**：
- HW0396（郦汝君）关联 **XH02** 群组（7 个三厂小簧生管/计划人员 7-22 共用），XH02 含完整 A01~A10 菜单权限 → 能派工
- HW0403 只有 SCXH-PLN001（无 A 系列菜单权限）→ 不能派工
- 注意：XH02 群组在 `TBLUSRGROUPBASIS` 主档中查不到（0 行），但 `TBLUSRUSERGROUP`/`TBLUSRGROUPPRIV` 记录齐全且 H5 端生效——权限机制只看权限记录本身

**第二层（H5 加载）**：改完权限后 H5 端需**重新登录**（权限是登录时拉取的会话快照）。

**排查链路（四张表，归属通用资产 `data/smes-621-sql/用户权限查询-SQL.sql`）**：

| 表 | 作用 | 本次实测结论 |
|----|------|------|
| `TBLUSRUSERBASIS` | 用户主档（USERNO/USERNAME/GUID/ISSUESTATE） | HW0403 方迪，正常 |
| `TBLUSRUSERGROUP` | 用户-作业群组关联（GROUPNO/GROUPTYPE/ISSUESTATE） | HW0403 仅 SCXH-PLN001 一个群组（HW0396 有 6 个） |
| `TBLUSRGROUPBASIS` | 群组主档（GROUPNO/GROUPNAME/ISSUESTATE） | SCXH-PLN001 三厂小簧计划组，正常；**XH02 查无主档仍生效** |
| `TBLUSRGROUPPRIV` | **群组权限明细（GROUPNO/PRIVTYPE/PRIVNO/PRIVISSUE）** | 对比 XH02 才见真差异：SCXH-PLN001 缺 A 系列菜单权限 |

## 排查步骤

```
node agent/mes-implement-expert/tools/query-mes.js data/smes-621-sql/用户权限查询-SQL.sql --profile home -p userno=HW0403 --show 1..4
```

1. **①用户**：确认用户存在、ISSUESTATE 正常
2. **②群组关联**：确认该用户绑定到哪个作业群组（GROUPNO + 群组名）
3. **③群组权限**：列出该群组全部 PRIVNO，对照 [h5-作业群组权限清单.md](../../../../agent/mes-implement-expert/data/smes-621/h5-作业群组权限清单.md) 检查派工/报工按钮权限是否齐全
4. **④控件禁用**：TBLUSRGROUPPRIVCONTROL 是否有该群组的 CONTROLNAME（禁用项）

## 判读闭环

- **缺菜单权限编号（PRIVTYPE=9）→ H5 端按钮/模块不显示（本次根因）**：先对照 XH02 等"能正常使用"的群组做 EXCEPT 权限差异，缺 A/B 系列菜单权限编号（A07 派工作业/A01 派工设定等）就补勾菜单权限。**只补平台权限编号（DISPATCH IMPORT/DISPATCH OPERATION 等 PRIVTYPE=0）对 H5 按钮无效**
- **库内菜单权限齐全但 H5 空白** → 才轮到前端：①重新登录 ②清浏览器缓存/无痕 ③找 DS（鼎捷）确认群组"发布生效"
- **对照组法**：找能正常用该功能的群组/用户（如 HW0396→XH02），EXCEPT 对比权限差异，是定位"缺哪个维度权限"的最快路径

## ⚠️ 坑

- **「权限齐全」要先分清维度**：平台权限编号（PRIVTYPE=0，英文编号）齐全 ≠ H5 菜单权限（PRIVTYPE=9，A/B 编号）齐全——SCXH-PLN001 就是平台编号看似全、A 系列菜单编号全缺
- **补权限要找对勾选项**：权限维护界面里「菜单权限」和「在线报工平台权限」是两个维度，H5 按钮看前者；用户后补的 DISPATCH IMPORT（PRIVTYPE=0）是平台权限，H5 端要 A06（菜单编号）才有效
- **XH02 群组主档在 TBLUSRGROUPBASIS 查无记录但仍生效**（用户关联+权限记录在），别用"主档存在"判断群组是否有效
- `TBLUSRUSERGROUP.GROUPTYPE` 共库 2467 条里几乎全为 `0`（仅 2 条 `5`），GROUPNO 才是群组键（无 GROUPID 列）
- `TBLSYSFUNCTION_USER` / `TBLSYSUSERMENU` 与作业群组权限无关（本次验证为空/自定义菜单），别误用
