# 排障卡：H5端派工调度中心页面空白/无作业按钮

> **系统**：sMES（共库 Home）｜ **厂区**：三厂小簧（表为 sMES 通用表，各厂适用）｜ **功能**：H5 端派工调度中心作业群组权限 ｜ **首次记录**：2026-08-21
> **来源**：用户投喂截图（inbox/派工调度中心_2026-08-21_16-12-02.jpg）+ 连库实测验证（HW0403 / SCXH-PLN001）

## 症状

- 用户能登录、左侧菜单能进「派工调度中心」、页面标题与「前置作业」页签正常显示
- **但页签下所有作业按钮全空白**（生产批开立/派工作业等一个都不显示）
- 用户反馈"作业群组权限都设置好了，还是没有派工权限"

## 关键判断：库内权限 vs H5端加载 两层

**第一层（数据库 TBLUSRGROUPPRIV，本次实测确认）**：权限记录在库里完整且生效时，**不代表** H5 端能立即看到——H5 端权限是**登录时拉取的会话快照，不实时刷新**。

**排查链路（四张表，归属通用资产 `data/smes-621-sql/用户权限查询-SQL.sql`）**：

| 表 | 作用 | 本次实测结论 |
|----|------|------|
| `TBLUSRUSERBASIS` | 用户主档（USERNO/USERNAME/GUID/ISSUESTATE） | HW0403 方迪，正常 |
| `TBLUSRUSERGROUP` | 用户-作业群组关联（GROUPNO/GROUPTYPE/ISSUESTATE） | SCXH-PLN001，7-28 建立，正常 |
| `TBLUSRGROUPBASIS` | 群组主档（GROUPNO/GROUPNAME/ISSUESTATE） | 三厂小簧计划组-小簧生产计划，正常 |
| `TBLUSRGROUPPRIV` | **群组权限明细（GROUPNO/PRIVTYPE/PRIVNO/PRIVISSUE）** | 116 项，派工权限齐全 |

**TBLUSRGROUPPRIV.PRIVTYPE 三值语义（实测归纳）**：
- `9` = 菜单权限编号（B0101 生产批开立/B0102 流程卡打印/B0106 批次开立…）
- `0` = 平台权限编号（LOT CREATE/DISPATCH OPERATION 派工作业/A03 派工看板…）
- `8` = 按钮级 CRUD（Add/Edit/Delete/View/Export…）

## 排查步骤

```
node agent/mes-implement-expert/tools/query-mes.js data/smes-621-sql/用户权限查询-SQL.sql --profile home -p userno=HW0403 --show 1..4
```

1. **①用户**：确认用户存在、ISSUESTATE 正常
2. **②群组关联**：确认该用户绑定到哪个作业群组（GROUPNO + 群组名）
3. **③群组权限**：列出该群组全部 PRIVNO，对照 [h5-作业群组权限清单.md](../../../../agent/mes-implement-expert/data/smes-621/h5-作业群组权限清单.md) 检查派工/报工按钮权限是否齐全
4. **④控件禁用**：TBLUSRGROUPPRIVCONTROL 是否有该群组的 CONTROLNAME（禁用项）

## 判读闭环

- **库内权限齐全但 H5 空白** → 前端会话快照未更新 → ①重新登录 ②清浏览器缓存/无痕 ③仍无效找 DS（鼎捷）确认群组是否"发布生效"（鼎捷权限维护常需发布；若权限记录加了很多天仍无效，基本是未发布/未绑定生效）
- **库内缺权限编号** → 群组里补勾选对应菜单权限编号，补后仍需用户重登生效
- **对照组**：找一个能正常使用该功能的厂区群组（如 DH01 一厂大簧），EXCEPT 对比权限差异，排除"系统本来就这样"

## ⚠️ 坑

- **B0101 等权限加了很多天仍看不到 ≠ 权限没配**：优先怀疑 H5 端发布/刷新，先让用户重登，别急着改库
- `TBLUSRUSERGROUP.GROUPTYPE` 共库 2467 条里几乎全为 `0`（仅 2 条 `5`），GROUPNO 才是群组键（无 GROUPID 列）
- 群组名信息在 `TBLUSRGROUPBASIS.GROUPNAME`（三厂小簧=SCXH-PLN001 前缀，一厂大簧=DH01 前缀），勿只认群组编号
- `TBLSYSFUNCTION_USER` / `TBLSYSUSERMENU` 与作业群组权限无关（本次验证为空/自定义菜单），别误用
