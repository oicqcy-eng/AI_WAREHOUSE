# 排障卡：首站扫码上料报「当前条码不存在MES中，确认是否已发料或已同步发料信息」

> **系统**：sMES（共库 Home） ｜ **厂区**：一厂大簧 ｜ **功能**：工单生产批开立后首站报工 → 扫码上料 ｜ **首次记录**：2026-08-15
> **来源截图**：`delivery/inbox/日常运维报错截图/一厂大簧_MES工单生产批开立后首站报工…-20260815-223122.png` + `平板报工界面-20260815-223349.png`（本地，不入 git）

## 症状

- 报错文字：「当前条码不存在MES中，确认是否已发料或已同步发料信息！」
- 场景：MES 首道报工扫原材料条码（Y1012608050277）校验工单-原材料绑定（匹配 U9 发料）
- 界面同时显示：物料 `11321-…`（B55SiCr-S淬弹簧钢）标准用量 2.7 / 本次应耗 4050 / **已发 0 / 状态 缺料**

## 根因

**U9 材料需求已同步到 MES，但领料/发料数量为 0（未发料，或发料未同步到 MES）**。判定依据（2026-08-15 连库实测，共库 home）：

1. 工单本体正常：`MO1012608050056`（界面显示 `MO01012608050056` 为位错，真实号第3位多 `1`）→ 产品 21101-002557 / MOQTY 1500 / 生产批 -001 / MOSTATE=3 已开工 / ISSUESTATE=2 需领料
2. **决定性（正确数据源 `Tbloemomateriallist`）**：标准用量 2.7 × 1500 = 理论领料 4050；**U9 材料需求 REQUIREQTY=4500（已同步到 MES），已领料 ORGMATERIALQTY=0，缺料=4500** → U9 需求在、实际出库为 0
3. 界面"已发 0/缺料"与库数据完全一致 → 扫的条码 Y1012608050277 在 MES 无发料绑定，自然报"条码不存在"

> ⚠️ **表选对很关键**：查发料用 `Tbloemomateriallist`（工单材料/发料正确表）。我初查 `TBLOEMOMATERIALINBASIS_ERP` 该工单 0 条（同系列有）曾误导为"同步没跑"，实为另一张链路表；用户提供 `Tbloemomateriallist` 后一跑即中——用户这份 SQL 为权威查询（见 `发料查询SQL-28.sql`）。
> ⚠️ 工单号注意：用户界面 `MO01012608050056`（16位） vs 库中 `MO1012608050056`（15位）——排查时先模糊 LIKE `%08050056%` 确认真实号，别因精确匹配 0 行误判为"工单不存在"。

## 排查步骤

1. 先用工单号后段模糊查真实号：`SELECT BASELOTNO,MONO FROM TBLWIPLOTBASIS WHERE BASELOTNO LIKE '%<工单后段>%'`
2. **查发料（权威 SQL，用户提供）**：`SELECT a.stdqty 标准用量, b.MOQTY 工单数, a.REQUIREQTY U9需求, a.ORGMATERIALQTY 已领, a.REQUIREQTY-a.ORGMATERIALQTY 缺料 FROM Tbloemomateriallist a LEFT JOIN Tbloemobasis b ON a.MONO=b.MONO WHERE a.MONO='<真实工单>'` → 见 `发料查询SQL-28.sql`（模板）
3. 判读：需求>0 且已领=0 → **U9 需求已同步、领料动作未发生/未同步**（本例 4500 vs 0）
4. 到 U9 侧核查：发料单是否生成/过账、是否特殊发料（委外/直发/倒冲）未走同步

## 已排除项

- ❌ 不是 MES 工单不存在（工单/生产批/产品均核对无误）
- ❌ 不是条码扫错（条码在发料数据无对应——因根本无领料记录）
- ❌ 不是 BOM 问题（标准用量 2.7、应耗 4050=1500×2.7、U9 需求 4500 均正确）
- ❌ 不是需求未同步（REQUIREQTY=4500 已落 MES `Tbloemomateriallist`）——缺的是领料/发料数量
