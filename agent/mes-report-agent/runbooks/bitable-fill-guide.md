# 汇报多维表格 · 团队操作说明

> **给谁看**：一线实施人员（填表1）、项目管理员陈宇（维护表2 + 每周收口）、新接手项目的同事。
> **配套文件**：
> - 表格本体：`delivery/inbox/汇报文档/工作记录表-规范化.base`（导入飞书即用）
> - 权威结构定义：`agent/mes-report-agent/data/report-bitable-spec.md`（字段/选项/仪表盘的唯一口径）
> - 数据治理成果：`agent/mes-report-agent/data/history-log-governance.md`（266 条归属修正明细）
>
> **一句话原则**：日志做事实流水，任务池做项目管理，仪表盘做管理展示，AI 周报读任务池。

---

## 0. 角色分工

| 角色 | 管哪张表 | 频率 |
|------|----------|------|
| 一线实施人员 | 只填表1「原始工作日志」 | 每天 ≤1 分钟/条 |
| 项目管理员（陈宇） | 维护表2「任务问题归集池」+ 每周收口 | 每周一次 ~15 分钟 |
| AI 周报 Agent | 读表2（主）+ 表1（佐证）→ 出周报 | 每周自动 |

> **边界**：一线**不碰**任务池、不做任务绑定、不维护视图——只在表1 里如实记录「今天做了什么」并回答「是否形成任务」。

## 1. 一次性：导入与核对（导入当天做一次）

1. 打开飞书云文档 → **新建 ▾ → 导入** → 上传 `工作记录表-规范化.base`（或直接拖进飞书）。
2. 导入成功后核对：
   - 表1 应有 **266 条**日志，表2 应有 **26 条**任务（8 原 + 18 补充）。
   - 表2 优先级里有 **P4**；日期列叫**发现日期 / 实际闭环日期**（不是记录日期/完成日期）。
3. 把新表重命名为正式名，如 **「MES项目-工作记录表」**，旧表改名加「-旧」并归档，避免填错表。

## 2. 表1「原始工作日志」填报规则（一线）

> 每天下班前把当天工作如实记成流水。**宁可多记几条短句，也不要一条记一大段。**

### 2.1 字段怎么填（12 个字段，必填 6 + 选填 6）

| # | 字段 | 必填 | 怎么填 |
|---|------|:----:|--------|
| 1 | 记录日期 | ✅ | 自动默认今天，不手改 |
| 2 | 所属项目 | ✅ | 从 7 项里选（三厂小簧/一厂大簧/二厂大簧/重庆/实验室Lims/无锡泽根/华纬其它）|
| 3 | 工作内容 | ✅ | **自由文本**，一句话讲清"对哪个模块做了什么"，如「三厂小簧 数采 10 个点位现场安装」|
| 4 | 结果类型 | ✅ | 8 选 1：`问题关闭` `方案确认` `配置完成` `培训完成` `数据完成` `上线验证` `风险暴露` `需求确认` |
| 5 | 是否形成任务 | ✅ | 这条日志要不要跟进到任务池？**是** → 管理员每周收口；**否** → 当日事当日毕 |
| 6 | 业务模块 | | 10 选 1（生产报工/工单管理/物料管控/质量模块/设备维保/安灯异常/设备数采/系统接口/报表看板/系统管理）|
| 7 | 项目阶段 | | 6 选 1（需求调研/方案设计/基础资料收集/培训上线/现场实施/运维优化）|
| 8 | 责任人 | | 默认自己，一般不用改 |
| 9 | 协作人 | | 有协作者就多选，没有留空 |
| 10 | 交付产出 | | 这条工作产出的实物/文档/数量，如「安装点位 10 个」「导出报表 5 张」|
| 11 | 任务问题归集池 | | **不填**（管理员后台绑定）|
| 12 | 附件 | | 截图/文件，有就传 |

### 2.2 三条铁律

1. **别选「是」就完事**：勾「是否形成任务=是」时，请在结果类型里同时写清是「风险暴露」还是「问题关闭」，方便管理员判断进不进池。
2. **结果类型是给 AI 看的关键维度**：别留空，每天 8 选 1 里挑一个最贴的。
3. **所属项目必须选**：266 条历史里 71 条归属错了，就是没认真选——周报按项目分，选错就归错项目。

### 2.3 示例对照

| ❌ 这样填（无效） | ✅ 这样填（有效） |
|---|---|
| 内容：「做系统」｜结果类型：空 | 内容：「三厂小簧 数采 10 个点位现场安装，2 个点缺电源」｜结果类型：风险暴露｜所属项目：三厂小簧sMES |
| 内容：「和供应商开会」｜结果类型：空 | 内容：「与鼎捷实施确认 SQL/IIOT 服务器部署顺序」｜结果类型：方案确认｜所属项目：重庆sMES项目 |

## 3. 表2「任务问题归集池」维护规则（管理员）

> **定位**：所有管理汇报的主数据源。只有**需要跟进到闭环**的问题才进池。

### 3.1 准入规则（判断进不进池）

| ✅ 进任务池 | ❌ 不进任务池 |
|------------|--------------|
| 停线风险 / 跨部门协调 | 普通会议 |
| 系统 BUG / 功能缺陷 | 日常测试 |
| 需求变更 / 范围调整 | 简单配置 |
| 领导关注事项 / 审厂要求 | 常规培训 |
| 计划内大模块上线节点 | 已完成且无需跟进的当日事项 |

### 3.2 字段怎么填（15 个字段，必填 7）

| # | 字段 | 必填 | 怎么填 |
|---|------|:----:|--------|
| 1 | 归集标题 | ✅ | 规范格式 **【项目简称-业务模块-核心问题】**，如 `三厂小簧-设备数采-现场点位电源未接` |
| 2 | 对应项目 | ✅ | 与表1 口径一致 7 项 |
| 3 | 问题来源 | ✅ | 现场反馈 / 系统异常 / 用户需求 / 会议决策 / 领导要求 / 审厂要求 |
| 4 | 优先级 | ✅ | **P1** 停线/重大风险 · **P2** 重大异常/跨月延期 · **P3** 一般问题 · **P4** 优化建议 |
| 5 | 发现日期 | ✅ | 问题首次暴露日 |
| 6 | 计划完成日期 | ✅ | 承诺闭环日（写具体日期，周报按此排期）|
| 7 | 任务状态 | ✅ | 待启动 / 进行中 / 暂缓 / 已闭环 |
| 8 | 进度百分比 | | 0~100%，进行中任务尽量更新 |
| 9 | 实际闭环日期 | | 状态变「已闭环」当天填 |
| 10 | 闭环判定标准 | | **「什么算完成」**，如「数采点位通电 + 数据进 MES」；缺失则闭环时说不清 |
| 11 | 周报归集分类 | ✅ | 本周完成 / 本周推进 / 重点问题 / 下周计划 / 长期跟踪（AI 分块依据）|
| 12 | 协调资源需求 | | 需要领导/跨部门支持的事写这里，会进周报「需协调」|
| 13 | 关联日志 | | 每周批量绑定本周相关日志（一条任务 ↔ 多条日志）|
| 14 | 附件 | | 佐证材料 |
| 15 | 卡点 & 问题描述 | | 一句话描述卡在哪、影响什么 |

### 3.3 生命周期（一条任务的标准流程）

```
发现（进池）→ 待启动 → 进行中 → 已闭环
  ↓ 写清楚         ↓ 每周更新        ↓ 填实际闭环日期 + 复核判定标准
  发现日期/优先级   进度百分比/分类     关联日志已完成
```

## 4. 视图建议（导入后手动建一次，约 10 分钟）

> 规范上限 **8 个视图**：表1 三视图 + 表2 四视图 + 仪表盘。原「表格」视图保留作底稿，其余按下表新增。

### 4.1 表1 三视图

| 视图 | 筛选条件 | 用途 |
|------|----------|------|
| 我的日报 | 记录日期 = 今日（责任人 可再按自己筛）| 员工个人导出日报 |
| 项目周流水 | 记录日期 ∈ 本周，按所属项目分组 | 管理员溯源任务配套日志 |
| 全量历史查询 | 无筛选 | 跨周期追溯 |

> 飞书操作：视图左上「⋯」→ 添加筛选条件 → 选字段 → 设条件；「记录日期」用「在（本周）」这类相对条件，**不要用固定日期**，否则每周要改。

### 4.2 表2 四视图（周报/月报/高层风险都靠筛选，不手动打标）

| 视图 | 筛选条件 | 用途 |
|------|----------|------|
| 项目任务总览 | 按「对应项目」+「任务状态」双层分组 | 日常进度管控 |
| 周报素材 | 发现日期 ∈ 本周 **或** 状态本周变更，按优先级排序 | **AI 周报主数据源** |
| 月报素材 | 本月新增 / 本月闭环 / 跨月未闭环 | 月度台账 |
| 高层风险 | 优先级 ∈ P1/P2 **且** 任务状态 ≠ 已闭环 | 直接截图给领导 |

### 4.3 仪表盘（1 套，给厂长/总监看）

| 模块 | 指标 |
|------|------|
| ① 各项目健康度 | 总任务数 / 进行中 / 已闭环 / 延期数量 |
| ② 风险分级看板 | P1/P2/P3 未闭环数量（P1 单独置顶预警）|
| ③ 业务模块实施进度 | 物料管控 / 设备数采 / 安灯 / U9接口 等完成率 |
| ④ 本周重点待协调 | 自动抓「协调资源需求」非空项 |

> 若多维表格仪表盘受限（多视图场景），退化为任务池「高层风险」视图即可，不阻塞。

## 5. 每周收口 SOP（管理员，固定 1 次，~15 分钟）

> 建议固定在每周五下午，周报输出前。

1. **筛日志**：表1 筛本周「是否形成任务 = 是」→ 核对有没有漏进池的任务。
2. **绑关联**：表2 对每条新任务，「关联日志」批量选择本周相关日志（一条任务 ↔ 多条日志）。
3. **更状态**：更新任务池的 状态 / 进度百分比 / 周报归集分类 / 计划完成日期；闭环的填实际闭环日期 + 复核闭环判定标准。
4. **确认风险**：看「高层风险」视图，P1/P2 未闭环项自动在列 → 若有新增，补充「协调资源需求」字段。
5. **出周报**（可选）：跑 `weekly-extract.js`（见 §6），素材 + AI 润色出周报。

## 6. 与周报生成对接（mes-report-agent）

数据流：**表2 任务池（主）+ 表1 日志（佐证）→ 周报四模块**。

```bash
# 全项目汇总周报素材
node agent/mes-report-agent/tools/weekly-extract.js --year 2026 --week 33

# 单项目周报素材（如一厂大簧）
node agent/mes-report-agent/tools/weekly-extract.js --year 2026 --week 33 --project 一厂大簧sMES
```

脚本读取 `data/task-pool-supplement.csv` 和 `data/history-log-governance.csv`。**真实使用时**：从飞书表1/表2 导出最新数据覆盖这两个 CSV 即可（字段对齐 `report-bitable-spec.md`）。

输出四模块：**本周完成事项 / 核心问题及风险 / 待办事项 / 下周重点计划**。

## 7. 常见问题 FAQ

| 问题 | 回答 |
|------|------|
| 旧的「周次」「月份」字段没了？ | 被删了。周报/月报按**日期范围**筛选，不再手动标周次/月份。 |
| 「是否形成任务」选了「是」然后呢？ | 管理员每周五收口时把它收进表2，不用你手动建任务。 |
| 关联日志怎么绑？ | 表2 对应单元格 → 点「选择已有记录」→ 勾选表1 相关日志，可多选。 |
| 我填错了表怎么办？ | 填表1 不会影响任务池；若误填了表2，直接改「任务状态」或删除记录即可。 |
| 历史 266 条要我自己改归属吗？ | 不用，规范化 .base 已按治理结果改好（71 条修正），导入即生效。 |
| 以后想自己看今天干了啥？ | 用「我的日报」视图：记录日期 = 今日，一条不落。 |
| 任务池任务太多怎么找？ | 用「项目任务总览」视图，按项目 + 状态分组定位。 |
