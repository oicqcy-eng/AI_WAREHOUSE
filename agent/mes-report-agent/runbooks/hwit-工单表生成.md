# HWIT 工单表生成（IT事项 格式）

> **定位（2026-09-12 用户定版）**：这是**个人重复登记消除器**，不是项目知识。
>
> 日常处理的事项本来记在自己的工作日志（`data/worklog/`，**真源**）。但公司另有一套必须填的
> IT管理部 ITIL 工单表，所以把日志里的**新增事项**转成公司表格格式，复制黏贴过去即可——
> **唯一目的就是少登记一遍**。
>
> 由此推出三条纪律：
> 1. **产物是消耗品**：`IT事项_<年>W<周>.xlsx` 黏贴进公司表格后即作废，不必长期留存、不必当交付物。
> 2. **只覆盖"日常处理的新增事项"**，不是整个工作日志的镜像。
> 3. **规则只沉淀到本文件 + 工具 header**（`tools/generate-hwit.js`），
>    **不进任何项目 `knowledge/`** —— 公司在重庆、LIMS、任何项目上都要填同一张表，它与具体客户项目无归属关系。

---

## 工具

```bash
node agent/mes-report-agent/tools/generate-hwit.js [输出路径]
# 默认输出 delivery/projects/hw-spring-mes/output/IT事项_<年>W<周>.xlsx
```

生成 `IT`（23 列事项）+ `CAT`（28 列下拉源）两页签，7 个下拉可用。

**实现要点**：SheetJS 生成工作簿 → `jszip` 载入 → 把公司原版 `<dataValidations>` XML
字符串拼接进 `xl/worksheets/sheet1.xml` → 重新打包。
**为什么绕这一圈**：SheetJS 社区版**写不了** `!dataValidation`（这正是历次"下拉又没了"的根因）；
`xlsx-populate` 虽能写，但会为未指定选项吐 `prompt="undefined"` 等垃圾属性，触发 Excel 修复提示。
拼接方案实测与公司原版**逐字一致**（954 字节）。

## 影响度 / 紧急性怎么来的（2026-09-12 重做）

这两列在 IT 页**没有源字段**，但工作台要靠它们算优先级，不能空着。

**做法：任务池的 `优先级` 当锚，关键词只在档内定位。**

理由：任务池里的 `优先级` 是**你自己下的判断**，比正则可靠。若由关键词自由推，会推出与你自己判断打架的档位
（首版就这样：17 条里 8 条不一致）。锚定后**矩阵反查必然回到同一档**，不一致归零。

```
任务池有优先级 P1~P4
  ├─ 影响度：关键词命中则用，否则取该档规范代表
  │   P1→10-高  P2→20-中  P3→20-中  P4→30-低
  ├─ 紧急性：由矩阵反查（保证 影响×紧急 = 任务池的档）
  │   关键词命中且相容就用关键词，否则按「高→中→低」取第一个相容值
  └─ 关键词与该档不相容（如判「低」却记 P1）→ 回退规范代表，报告里列一条提示

任务池没写优先级
  └─ 纯关键词；两个都没命中就**留空**，报告里列「待你指定」（不硬猜）
```

**关键词表**（命中即取，按序短路）：

| 列 | 10-高 | 20-中 | 30-低 |
|---|---|---|---|
| 影响度 | 停线/停产/全线/全厂/无法使用/不可用/阻塞/阻断/上线前必须/影响结算/数据错误/跨组织 | 工序/卡控/绕行/批号/上料/校验/接口/同步/导入/部署/请购/审批 | 查询/优化/整理/归档/文档/手册/培训/点检资料/纪要 |
| 紧急性 | 逾期/已延期/紧急/加急/停线/阻塞/本周必须/上线前 | 计划/截止/推进/跟踪 | 长期/暂缓/待定/观察 |

> **不再按「已闭环/暂缓 → 紧急低」强制**：那会让矩阵反查失败，与任务池档位打架。
> 关闭与否由 `处理状态` 列（`61-关闭`）表达，不由紧急性表达。

## 入选规则（`collect()`）

三条并集，每条都在报告里标注**入选理由**，不静默：

| 理由 | 条件 |
|---|---|
| 本期新增 | `发现日期` 落在区间内 |
| 本期闭环 | `实际闭环日期` 落在区间内 |
| 本期日志关联 | `_id` 出现在区间日志的「关联任务」里（本期有实际动作） |

**内部动作剔除**（命中即不入选，但报告里逐条列理由）：
`投喂|归档|提炼|沉淀|知识卡` 与 `IT事项工单表|工单表按周生成|HWIT`（工具自身建设，写进去会自我指涉）。

> ⚠️ **剔除规则只扫「归集标题」，不扫「卡点&问题描述」**。描述里全是业务过程词，
> 实测「入库」会命中「IQC→派工→制样→报工→PQC→完工→**入库**」这种正常流程描述，把真事项误剔。
> 内部动作的标题本身就是动作，标题足够。

**已知需你手工补的列**：`提出人`（L 列）。任务池无该字段，且它是**事实断言**——
按 worklog 契约「是事实断言则禁止兜底」，只能你填。报告里按「问题来源」分组列出，
可整批填（如「现场反馈 → 第 1/8/9 行」）。

## 已知需手工补的列

**提出人（L列）**：任务池无此字段，是事实断言（不是排序单位元），按契约禁止兜底。报告按「问题来源」分组列出，可整批填。

**提出部门（K列）**：从标题自动提取——标题格式为「厂区-部门-内容」，取第一个 `-` 后的部分（如 `质量模块`、`设备数采`）。拿不准回退 `IT管理部`。

**日期格式**：日期列（M/O/P/Q）写字符串 `yyyy-mm-dd`，不写数字序列号——因为 `inject()` 注入时会丢失 `z` 格式属性。

## 哪些列我们**不填**（交工作台算）

| 列 | 字段 | 处理 | 理由 |
|---|---|---|---|
| **G** | **优先级** | **恒空** | **G 列无下拉**。工作台数据质量规则原文：「优先级异常｜原值无效且无法通过矩阵计算 → 优先级显示待完善」→ 优先级由工作台按 ITIL 矩阵计算，Excel 侧不该填 |
| U / V / W | 响应持续时间 / 计划完成-实际完成 / 实际完成持续时间 | **恒空** | V0 里是 `=P2-M2` `=Q2-R2` `=R2-M2` 公式，V1 已弃用，交工作台算 |

> **「留空」≠「越界」**。`verify()` 把两者分开报：**越界**是写进了枚举外的值（错误，会让工作台报数据质量问题）；
> **留空**是拿不准时有意不填（设计的一部分，比硬猜一个枚举值诚实），单独计数交你指定。
> 目前可能留空的是 `提出公司`（无编码依据的厂区）和 `应用分类`（CAT 无对应选项，如 LIMS）。

**优先级矩阵**（影响度 × 紧急度）：

| | 紧急 高 | 紧急 中 | 紧急 低 |
|---|---|---|---|
| **影响 高** | P1 | P1 | P2 |
| **影响 中** | P1 | P2 | P3 |
| **影响 低** | P2 | P3 | P4 |

**SLA**：P1 响应≤15min / 解决≤4h；P2 ≤30min / ≤8h；P3 ≤2h / ≤1工作日；P4 ≤1工作日 / ≤3工作日。

## 工作台规则（`IT管理部工作台配置.xlsx`）

- **「CAT 是 V1 状态定义的唯一事实来源」** —— 不得在配置文件里另维护一份状态映射
- **关闭状态仅 `61-关闭` / `65-关闭-用户撤销`**
- **个人范围按「处理人」判定** → 处理人必须与「人员配置」姓名一致，否则该事项保留但提示"负责人待维护"
- 序号为空、或「页码+序号」重复 = **错误级**（事项关联键失效）
- 临期规则：默认未来 **3 个工作日**，仅排除周六周日（`DUE_SOON_BUSINESS_DAYS`）
- 事项标识用 `buildIssueId(sheetName, sequence)`，**不用 Excel 行号**
- 默认事项池来源页 `DEFAULT_SOURCE_SHEET = IT`

## V0 → V1 演进（`#NAME?` 真因）

V0 `HWIT_服务.xlsx` 的 G 列是：

```
=IF(OR(E2="",F2=""),"",LET(_xlpm.impact,TEXTAFTER(E2,"-"),_xlpm.urgency,TEXTAFTER(F2,"-"),
_xlpm.p,INDEX(优先级矩阵!$B$4:$D$6,MATCH(...),MATCH(...)),
LEFT(E2,FIND("-",E2)-1)&"-"&_xlpm.p&"-"&XLOOKUP(...)))
```

用了 `LET` / `TEXTAFTER` / `TEXTBEFORE` / `XLOOKUP`（`_xlpm.` 前缀是 Excel 的内部 LAMBDA 参数命名空间）
—— **旧版 Excel 解析不了，才显示 `#NAME?`**。公式本意输出 `20-P1-紧急` 这类复合值（`影响度码-P级-SLA名`）。
**V1 已弃用该公式**，改为纯文本列 + 工作台计算。

## 原版 CAT 缺陷（本工具已修正）

V1 `IT事项.xlsx` 的 `W2:W4` / `AA2:AA4`（影响度/紧急度下拉源）内容损坏为 `[29, 29, "30-低"]`
—— 混入数字 29 且只剩 1 个标签，下拉实际不可用。工具按 IT 页样例行实际取值修正为
**`10-高` / `20-中` / `30-低`**。

## 陷阱

- **不许把「投喂归档」类动作写进事项表** —— 归档/提炼/建立知识卡是**内部动作**，不是日常处理的新增事项。
  工具只提炼**实质工作事项**。
- 厂区 → 「提出公司/职能中心」编码需人工核对，不要凭厂区名硬套（见下"待确认"）。
- 事项内容以**当周工作日志/任务池**为准；跨周未闭环的遗留事项才保留。
