# MES 项目周报生成流程 — V1

> **目标**：完成「生成2026年第XX周MES项目周报」→ 周报成稿的最小闭环。
> **原则**：不引入复杂自动化（无 API 集成、无数据库），一条命令出素材 + 一次 AI 润色成稿。
> **状态**：✅ V1 可用（2026-08-08）

---

## 数据流总览

```
你输入：生成2026年第XX周MES项目周报 [可选：某某项目]
   ↓ ① 数据准备（自动，本地权威数据源）
tools/export-range.js <周起> <周止>   ← 从 data/worklog/ 提取
   ↓ 输出：区间日志（按项目分组）+ 任务池全量 + P1/P2未闭环风险
   ↓ ② 生成（读素材 + prompt 模板）
prompt/weekly-report-v1.md
   ↓ ③ 成稿
项目经理周报（全项目汇总 或 单项目）
```

> **数据源变更（2026-08-09 本地化后）**：任务池/日志已迁至本地 `data/worklog/`（task-pool.json + logs/YYYY-MM.json），不再从飞书导出 CSV。取数一律走 `export-range.js`（见 §1）。
> **2026-09-11**：旧的 CSV 预分组工具 `tools/weekly-extract.js` 已删除 —— 它读的是飞书时代的 `data/task-pool-supplement.csv` 与 `data/history-log-governance.csv`（数据源已不存在），且其英文 status 枚举根本不属于 worklog 契约。四模块分组改由 AI 读 `export-range.js` 素材后直接组织。

## 使用方法

### 1. 准备数据源（本地 worklog/，2026-08-09 起）

**权威数据源 = `data/worklog/`**（task-pool.json + logs/YYYY-MM.json），直接读取，**不再从飞书导出**。

| 数据 | 位置 | 读取方式 |
|------|------|----------|
| 任务池（主数据源） | `data/worklog/task-pool.json` | `export-range.js` 直接读 |
| 原始工作日志（过程佐证） | `data/worklog/logs/YYYY-MM.json` | `export-range.js` 直接读 |

> **默认方式（唯一推荐）**：`export-range.js <周起> <周止>` 一次输出周报蒸馏数据包（①区间日志→完成事项/叙述佐证；②窗口任务变化＝新发现/闭环/卡点更新含尾注→本周动态；③项目状态快照→待办计数；④P1/P2 未闭环风险含原因），Claude 按四模块组织成稿（见 §2）。
>
> `--todos` 追加未闭环任务清单（P3/P4/待启动/暂缓，写全项目"待办事项"时用）；`--all` 回显含已闭环的任务池全量。字段契约与卡点更新纪律见 `data/worklog/SCHEMA.md`。
>
> **取数只有 §1 一条路**：`export-range.js`。旧的四模块预分组工具 `weekly-extract.js` 已于 2026-09-11 删除（读飞书时代 CSV，数据源已不存在），四模块分组改由 AI 读素材后组织。

### 3. 生成周报（AI 润色成稿）

把素材文件内容 + `prompt/weekly-report-v1.md` 模板交给 Claude/AI：

```
请读取 tmp/weekly-input-2026-W32.md 的数据，按 prompt/weekly-report-v1.md 的
四模块结构生成「2026年第32周 MES 项目周报」（全项目汇总）。
```

或直接对 Claude 说：
```
生成2026年第32周MES项目周报 —— 数据在 tmp/weekly-input-2026-W32.md，
按 agent/mes-report-agent/prompt/weekly-report-v1.md 模板输出。
```

---

## 四模块说明

| 模块 | 数据来源 | 生成逻辑 |
|------|----------|----------|
| 本周完成事项 | 任务池「已闭环/本周完成」+ 日志完成型记录 | 做了什么 → 达成什么结果 |
| 核心问题及风险 | 任务池 P1/P2 未闭环 + 日志暴露新问题 | 问题/影响/卡点/需协调，P1 在前 |
| 待办事项 | 任务池 待启动/进行中/暂缓 | 事项/状态/计划完成日期 |
| 下周重点计划 | 任务池「下周计划」+ 计划完成在下周 | 要做什么/闭环标准 |

### 样例周报（AI 润色后，示意）— 模式 B 单项目

```markdown
# 三厂小簧sMES · MES 项目周报（2026年第32周，2026-08-03 ~ 08-09）

## 一、本周完成事项
- 完成数采点位安装 10 个（2026-08-05 现场安装）。

## 二、核心问题及风险
- [P1] 数采部署与设备参数提供：倒角机等参数未确认，数据采集未完全打通。
  **影响**：设备数采模块验收延后。**需协调**：数采实施方驻场。
- [P2] 车间网络无线信号差（数采实施方反馈）：影响数采联调稳定。**需协调**：网络公司勘测。

## 三、待办事项
- 数采部署与设备参数提供（进行中，计划 2026-08-31 闭环）
- 车间网络无线信号改善（进行中，计划 2026-08-31）
- 展示大屏安装与电源布线（进行中，计划 2026-08-31）

## 四、下周重点计划
- 推进数采数据全量采集打通；协调网络公司解决车间信号；确认大屏电源布线方案。
```

## 完整工具链（V1.1 补充）

### MD 版 → DOCX 版（WPS 打开用）
```bash
node agent/mes-report-agent/tools/md-to-docx.js delivery/projects/hw-spring-mes/output/reports/2026-XX-WXX.md delivery/projects/hw-spring-mes/output/reports/2026-XX-WXX.docx "标题"
```

### HTML 投影汇报版（控制台风）
```
触发条件：用户说"汇报版""主持人版""生成汇报页"
自动调用 /report-board skill，生成深墨蓝底 HTML
```

### 完整流程
```
生成2026年第XX周周报
  ↓
① export-range.js <周起> <周止>
  → 输出：周报蒸馏数据包（区间日志+任务池+风险）
  ↓
② AI 读 prompt/weekly-report-v1.md 润色成稿
  → 输出：周报.md（delivery/projects/hw-spring-mes/output/）
  ↓
③ md-to-docx.js
  → 输出：周报.docx（WPS 友好）
  ↓
④ [可选] report-board skill
  → 输出：周报_汇报版.html（投影汇报）
```
