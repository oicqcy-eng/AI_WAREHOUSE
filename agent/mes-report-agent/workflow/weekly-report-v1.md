# MES 项目周报生成流程 — V1

> **目标**：完成「生成2026年第XX周MES项目周报」→ 周报成稿的最小闭环。
> **原则**：不引入复杂自动化（无 API 集成、无数据库），一条命令出素材 + 一次 AI 润色成稿。
> **状态**：✅ V1 可用（2026-08-08）

---

## 数据流总览

```
你输入：生成2026年第XX周MES项目周报 [可选：某某项目]
   ↓ ① 数据准备（自动，本地权威数据源）
tools/export-range.js <周起> <周止>   ← 从 data/worklog/ 提取
   ↓ 输出：区间日志（按项目分组）+ 任务池全量 + P1/P2未闭环风险
（或 tools/weekly-extract.js --year YYYY --week NN 做四模块预分组，见下）
   ↓ ② 生成（读素材 + prompt 模板）
prompt/weekly-report-v1.md
   ↓ ③ 成稿
项目经理周报（全项目汇总 或 单项目）
```

> **数据源变更（2026-08-09 本地化后）**：任务池/日志已迁至本地 `data/worklog/`（task-pool.json + logs/YYYY-MM.json），不再从飞书导出 CSV。优先用 `export-range.js` 取原始数据；`weekly-extract.js` 保留四模块预分组能力，但需先把 worklog 导出为它认的 CSV 才能用（见 §1 备注）。

---

## 使用方法

### 1. 准备数据源（本地 worklog/，2026-08-09 起）

**权威数据源 = `data/worklog/`**（task-pool.json + logs/YYYY-MM.json），直接读取，**不再从飞书导出**。

| 数据 | 位置 | 读取方式 |
|------|------|----------|
| 任务池（主数据源） | `data/worklog/task-pool.json` | `export-range.js` 直接读 |
| 原始工作日志（过程佐证） | `data/worklog/logs/YYYY-MM.json` | `export-range.js` 直接读 |

> **默认方式**：`export-range.js <周起> <周止>` 输出日志+任务池+P1/P2 风险，Claude 按四模块组织成稿（见 §2）。
>
> **若要用 weekly-extract.js 的四模块预分组**：需先 `export-excel.js task --out=tmp/tasks.csv` / `log --out=tmp/logs.csv` 转 CSV，再跑 `weekly-extract.js --year --week --tasks tmp/tasks.csv --logs tmp/logs.csv`（列名须匹配脚本约定）。此路径为兼容保留，新流程推荐 export-range.js。

### 2. 生成数据素材（一条命令）

```bash
# 全项目汇总周报
node agent/mes-report-agent/tools/weekly-extract.js --year 2026 --week 32

# 单项目周报（如一厂大簧、三厂小簧）
node agent/mes-report-agent/tools/weekly-extract.js --year 2026 --week 32 --project 三厂小簧sMES
```

输出：`tmp/weekly-input-2026-W32.md`（或 `weekly-input-2026-W32-三厂小簧sMES.md`）

### 3. 生成周报（AI 润色成稿）

把素材文件内容 + `prompt/weekly-report-v1.md` 模板交给 Claude/AI：

```
请读取 tmp/weekly-input-2026-W32.md 的数据，按 prompt/weekly-report-v1.md 的
四模块结构生成「2026年第32周 MES 项目周报」（全项目汇总）。
```

或直接对 Claude 说：
```
生成2026年第32周MES项目周报 —— 数据在 tmp/weekly-input-2026-W32.md，
按 agent/mes-report-agent/prompt/weekly-report-v1.md 模板输出。
```

---

## 四模块说明

| 模块 | 数据来源 | 生成逻辑 |
|------|----------|----------|
| 本周完成事项 | 任务池「已闭环/本周完成」+ 日志完成型记录 | 做了什么 → 达成什么结果 |
| 核心问题及风险 | 任务池 P1/P2 未闭环 + 日志暴露新问题 | 问题/影响/卡点/需协调，P1 在前 |
| 待办事项 | 任务池 待启动/进行中/暂缓 | 事项/状态/计划完成日期 |
| 下周重点计划 | 任务池「下周计划」+ 计划完成在下周 | 要做什么/闭环标准 |

## 二、核心问题及风险（2 条）
- [P1] 三厂小簧-设备数采-数采部署与设备参数提供｜状态:进行中｜发现:2026-7-7｜计划:2026-8-31｜来源:现场反馈
  - 需协调：数采实施方
- [P2] 三厂小簧-设备数采-车间网络无线信号差｜状态:进行中｜发现:2026-7-10｜计划:2026-8-31｜来源:现场反馈
  - 需协调：网络公司

## 五、本周原始日志佐证（2 条）
- 2026-8-5｜三厂小簧安装数采10个
- 2026-8-7｜现场实施

### 样例周报（AI 润色后，示意）— 模式 B 单项目
```markdown
# 三厂小簧sMES · MES 项目周报（2026年第32周，2026-08-03 ~ 08-09）

## 一、本周完成事项
- 完成数采点位安装 10 个（2026-08-05 现场安装）。

## 二、核心问题及风险
- [P1] 数采部署与设备参数提供：倒角机等参数未确认，数据采集未完全打通。
  **影响**：设备数采模块验收延后。**需协调**：数采实施方驻场。
- [P2] 车间网络无线信号差（数采实施方反馈）：影响数采联调稳定。**需协调**：网络公司勘测。

## 三、待办事项
- 数采部署与设备参数提供（进行中，计划 2026-08-31 闭环）
- 车间网络无线信号改善（进行中，计划 2026-08-31）
- 展示大屏安装与电源布线（进行中，计划 2026-08-31）

## 四、下周重点计划
- 推进数采数据全量采集打通；协调网络公司解决车间信号；确认大屏电源布线方案。
```
