## 2. 字段口径（沿用 report-bitable-spec.md §1/§2）

**日志记录**（必填 5 + 可选 7）：

`归集标题` · `对应项目` · `问题来源` · `优先级` / `发现日期` · `计划完成日期` · `实际闭环日期` · `任务状态` · `进度百分比` · `闭环判定标准` · `周报归集分类` · `协调资源需求` · `卡点&问题描述`

**选项枚举**（与飞书表完全一致）：
- 所属项目 7 项：三厂小簧sMES / 一厂大簧sMES / 二厂大簧sMES / 重庆sMES项目 / 实验室Lims项目 / 无锡泽根sMES项目 / 华纬其它项目
- 结果类型 8 项：问题关闭 / 方案确认 / 配置完成 / 培训完成 / 数据完成 / 上线验证 / 风险暴露 / 需求确认
- 优先级：P1/P2/P3/P4 · 任务状态：待启动/进行中/暂缓/已闭环 · 周报归集分类：本周完成/本周推进/重点问题/下周计划/长期跟踪
- 问题来源：现场反馈/系统异常/用户需求/会议决策/领导要求/审厂要求
- 业务模块 10 项、项目阶段 6 项：见 spec §1.1

### 2.1 日志表达规范：当日动作 vs 整体进度（2026-08-11 用户定版）

**日志记「当日动作」，任务记「整体进度」——两层分写，不混淆。**

产生歧义的典型：「三厂小簧安装数采10个」——「10个」读起来像总量（装完就完），实际是当日动作量（整体109个）。误读会导致周报/任务进度口径错乱。

**日志写法**（当日动作 + 量纲 + 累计进度，三要素至少写清量纲）：
> 三厂小簧数采盒子安装：当日安装10个（累计数待核实，整体109个），整体部署进行中

**数量类数据拿不准 → 跳出决策问用户，不硬猜**：
- 涉及**累计进度/总数/已装数量**等数字，从上下文读不出时，**不自行推算**（如「当日10个」推断「累计=10」是错的，可能之前已装过）——直接问用户补充实际数字
- 用户暂未给数 → 记录里标「**待核实**」（工作内容/卡点/进度百分比都标），后续有数再补
- 同理，`进度百分比` 拿不准时不填，不编造精确进度

> 教训：8-05 数采日志我凭「当日10个」自行填了「累计10/109」，实际 7-03 已协助部署过一批，累计数需用户核实，8-11 改标「待核实」。

**任务写法**：任务状态/进度反映整体——`卡点&问题描述` 写「整体N个：X月X日当日完成Y个（累计Y/N）」；拿不准的累计/总数用「**待核实**」标注，不硬填。

**结果类型怎么标**（「当天完成算不算完成」按层面分）：
- **日志层面**：当日动作做完 → 标对应完成类（如安装/部署 → `配置完成`），标完成没问题
- **任务层面**：整体没完 → 任务保持 `进行中`，不能闭环

> 教训来源：8-05 三厂数采安装日志「安装数采10个」被误读为「剩余数采10个」，周报风险栏/任务卡点/汇总四处写错，8-10 修正为「8-05已安装10个」后又补充「整体109个」才完全澄清（2026-08-11）。

## 3. 缺省值策略（沿用 spec §4.4）

### 3.1 字段解读优先级（2026-08-10 用户定版）

**用户明确要求：尽可能从用户描述/分享信息解读最合适的字段选项；解读不了或拿不准的，随时给用户选择，不硬猜、不偷懒。**

按此优先级取字段：
1. **从用户描述/纪要/上下文解读**最贴合选项（如「扫码上料卡住」→ 业务模块=物料管控、结果类型=风险暴露；「演示会定稿」→ 结果类型=方案确认）
2. **解读不到** → 看是否有上下文可推断（如项目、协作人从用户语境推断）
3. **拿不准/选项有实质分歧**（影响周报口径或业务判断的）→ **直接问用户给选择**，不默默落缺省
4. **确实无信息** → 才落最低档（下表）

> 注意：第 3 步的「问」不是每字段都问，而是**关键字段**（结果类型/是否形成任务/优先级/业务模块/项目阶段）拿不准时问；可推断的字段（项目/日期/责任人）尽量自己定。

### 3.2 最低档缺省值（仅在第 3.1 第 4 步用）

| 字段 | 默认 |
|------|------|
| 结果类型 | `需求确认` |
| 优先级 | `P4` |
| 项目阶段 | `需求调研` |
| 任务状态 | `待启动` |
| 是否形成任务 | `否` |
| 业务模块 | `系统管理` |
| 所属项目 | 上下文推断；推断不了询问 |
| 记录日期 | 处理当天 |

## 4. 任务池准入规则（沿用 spec §4.2）

**进 task-pool**：停线风险 / 跨部门协调 / 系统BUG / 需求变更 / 领导关注 / 审厂要求
**只记日志**：普通会议 / 日常测试 / 简单配置 / 常规培训

**AI 主动判定（2026-08-10 用户定版）**：AI 分析日志/纪要/数据时，主动识别**非流水账事项**（有意义/需汇报/可汇报，含拿不准的），**主动形成任务表数据**，不依赖用户显式标「是否形成任务=是」。即：标「否」或用户未提，只要 AI 判定有跟进价值就建任务；宁建不漏（多建可降 P4/暂缓，漏建错失跟进）。

## 5. 操作规范

| 场景 | 操作 |
|------|------|
| **打开录入页**（日常直接录入） | **双击 `start-worklog.bat`** → 浏览器自动打开 → 下拉选择/填写 → 保存 |
| 查字段契约 | `node agent/mes-report-agent/tools/worklog-append.js schema`（字段全集/必填/默认/结果类型词表） |
| 找关联任务 | `node agent/mes-report-agent/tools/worklog-append.js search-task '<关键词>'`（未闭环优先，返回 `_id` 供关联） |
| 追加日志 | `node agent/mes-report-agent/tools/worklog-append.js log '<json>'` |
| 追加任务 | `node agent/mes-report-agent/tools/worklog-append.js task '<json>'` |
| 提取区间数据（周报/月报素材） | `node agent/mes-report-agent/tools/export-range.js <起> <止>` |
| 汇报 docx | `node agent/mes-report-agent/tools/md-to-docx.js <输出目录>` |
| **生成仪表盘** | `node agent/mes-report-agent/tools/generate-dashboard.js [输出路径]` |
| **导出 Excel**（发人/存档） | `node agent/mes-report-agent/tools/export-excel.js log\|task\|all [--project=X] [--month=YYYY-MM] [--out=路径]` |

**追加时的纪律**：
- **先 `schema` 看字段契约 → 写日志前用 `search-task '<关键词>'` 找应关联的任务 `_id`**（免去手工翻 task-pool.json 探测字段/任务）
- 日志按 `记录日期` 的月份自动写入对应 `logs/YYYY-MM.json`；任务追加到 `task-pool.json`
- 追加前**先读对应文件**确认不重复（同一件事不重复入库）
- 修改记录：录入页【编辑】或 CLI `update-log/update-task`（按 `_id` 定位）；**部分字段更新即可，未传字段保留原值**（实现为原记录+patch 合并，见 §10 坑1）
- 删除记录：直接 Edit 对应 json（保留合理的修订留痕，见 always-settle-knowledge 原则）
- **数据源是本地**：生成汇报前用 export-range.js 取数，不再调飞书 API
- **补录历史日志默认只更新数据层**（2026-08-11 用户定版）：补录/补充历史事项时，只改日志 + 任务池（+dashboard 数据源可视化），**不动周报/月报/简报**；只有用户明确要求「更新周报/出月报」等才做汇报输出动作

## 6. 汇报链路（不变）

export-range.js 提取区间日志+任务池 → Claude 按 `report-bitable-spec.md` §9 规范组织 md → md-to-docx.js 生成 docx（微软雅黑 8pt 表格、无来源信息、去总监字眼）。

### 6.1 周报取数口径（2026-08-10 用户定版）

**主数据源 = 任务池**；日志按结果类型参与周报，关键类日志即使「是否形成任务=否」也能上报表：

| 日志结果类型 | 周报去向 |
|------|------|
| `风险暴露` | 周报**核心问题及风险**栏（即使标「否」） |
| `问题关闭`/`方案确认`/`配置完成`/`培训完成`/`数据完成`/`上线验证` | 周报**本周完成事项**栏（即使标「否」，同类归并） |
| `需求确认` | **不进周报正文**（除非建任务进池） |

> **操作提示**：写日志时结果类型选准即可，不必为了上报表而刻意标「是」——关键类日志自动进周报；建任务只影响「任务池/待办」口径，不影响「完成/风险」展示。
>
> **月报触发**（§9.4）：不固定出，按需手动触发（领导要月度口径/月度里程碑/月度收口时），不作每月固定出。

## 8. 录入页（替代飞书"打开直接录入"）

**启动**：双击仓库根 `start-worklog.bat` → 自动启动本地服务 + 打开浏览器录入页（http://localhost:8787）→ 关窗口即停止。

**组成**：
- `tools/worklog-server.js` — 本地 HTTP 服务（GET/POST，读写 worklog/，复用 worklog-append.js 的写入逻辑）
- `tools/worklog-ui.html` — 录入页（日志/任务双 tab，下拉选项来自 `/api/options`，保存后右侧实时显示最近记录与今日统计）
- `start-worklog.bat` — 一键启动脚本

**能力**：日志（项目/模块/阶段/结果类型/是否形成任务/责任人/协作人/交付产出 + 工作内容）与任务（标题/项目/来源/优先级/状态/发现/计划/实际闭环/进度/周报分类/协调资源/卡点）均可**录入**，必填校验 + 缺省值补齐与 CLI 完全一致。

**编辑**（2026-08-10 新增）：右侧最近记录每条带【编辑】按钮 → 点击加载到表单（顶部出现黄色横幅）→ 改完点「保存修改」按 `_id` **覆盖原记录**；点「取消编辑」放弃。改日期会跨月自动移动归档。覆盖后数据源即更新，周报/月报/仪表盘重新生成即反映修正。

**附件**（2026-08-10 新增）：日志/任务记录可带 `附件` 字段（可选），文件放 `worklog/attachments/` 下，录入页表单填文件名即可，最近记录会显示 📎 图标点击直接打开原始文档（如聊天记录/截图/表格）。Excel 导出时附件列一并带出。

**搜索**（2026-08-14 新增）：最近记录区顶部有搜索框，日志/任务两个 tab 均可用，按关键字搜索（回车或点 🔍），跨月匹配（大小写不敏感），命中关键词在结果中高亮，显示命中总数：
- 日志 tab → `GET /api/logs/search?q=&n=`，匹配 `工作内容/所属项目/业务模块/结果类型/责任人/协作人/交付产出`
- 任务 tab → `GET /api/tasks/search?q=&n=`，匹配 `归集标题/对应项目/问题来源/任务状态/协调资源需求/卡点&问题描述/闭环判定标准/周报归集分类`，搜索态额外显示卡点摘要行
- n 默认 50，返回 `{data, total}`；点 ✕ 清空回到最近记录；切换 tab 自动重置

**删除**（2026-08-14 新增）：右侧最近记录每条带【删除】按钮（红色），点击弹确认框（含被删内容摘要）→ 确认后调 `POST /api/logs/delete` / `POST /api/tasks/delete`（body `{_id}`）按 `_id` 从数据源物理删除，不可恢复；删除后自动刷新列表与今日统计。**正在编辑的就是被删记录时**自动取消编辑态。CLI 亦支持 `delete-log '<{_id}>'` / `delete-task '<{_id}>'`。

**注意**：服务进程存在期间 worklog 文件由它管理；对话框/CLI 追加与录入页追加**共用同一数据源**（worklog/），实时可见，无同步问题。端口 8787 可被 `WORKLOG_PORT` 环境变量覆盖。

## 9.5 模块上线进程日志（2026-08-10 用户定版）

**目的**：让用户看日志表时**一眼看出整个项目模块上线进程**——每个功能模块从「启动 → 收集资料 → 培训 → 上线运行」的完整轨迹。

**规则**：
1. **触发**：日志描述里出现**系统新功能模块**（业务模块枚举中某项，首次在某项目推进/上线），或已有模块进入**新里程碑阶段**
2. **动作**：为该模块**单独列一条「模块上线进程」日志**（同一项目同一业务模块一条）
3. **识别格式**：工作内容以 **`【模块上线进程】`** 开头，一眼可辨
4. **演进**：模块进入新阶段时，用 `update-log` **扩充这条进程日志**（保留历史阶段，追加新进展），一条日志承载该模块全部进程
5. **字段**：`业务模块`=该模块；`项目阶段`=模块当前所处阶段（需求调研/方案设计/基础资料收集/培训上线/现场实施/运维优化）
6. **与任务区分**：模块进程是「进度追踪」**不是**问题任务，默认 `是否形成任务`=否；模块内具体问题/阻塞才进 task-pool

**工作内容模板**：
```
【模块上线进程】<项目>-<业务模块>：启动(日期/方式) → 资料收集(日期) → 培训/配置(日期) → 上线运行(日期) → 后续优化(日期) ...
```

**查看方式**：导出 Excel 后按 `业务模块` 筛选，或看工作内容带 `【模块上线进程】` 前缀的记录。

**枚举外模块处理（2026-08-10 用户定版）**：
- 遇到 `业务模块` 枚举里**没有**的模块（如未来可能出现的 追溯/SPC/安灯报表 等）→ **扩展枚举**：先在定义处（`report-bitable-spec.md` §1 表、`worklog-server.js` `modules` 数组，两处）新增该项，再为该模块建进程日志
- 不把枚举外模块硬塞进现有相近项（会错分类、污染统计）
- 同步更新「N项」计数

## 10. 常见踩坑清单（2026-08-10 教训沉淀）

> 每次改数据/工具出问题先查这里，避免重复踩坑。相关工具：`tools/worklog-append.js`、`worklog-server.js`。

1. **update-log/update-task 是「原记录 + patch 合并」，不是整体替换**
   - 只传要改的字段，**未传字段保留原值**（实现 `Object.assign({}, found, patch)`）
   - 曾因用 patch 整体替换，导致 `归集标题/对应项目/优先级/协调资源` 被抹掉、`发现日期` 被误覆盖成处理当天——数据被破坏后才从 git HEAD 找回
   - **改前先看原记录**（读当前 json 或 `git show HEAD:<file>` 对拍），避免漏字段

2. **日期加减不要用 `toISOString()`**（UTC 时区，中国 +8 会少一天）
   - `new Date(d+'T00:00:00'); t.setDate(t.getDate()+N);` 后**用 getFullYear/getMonth/getDate 拼** `YYYY-MM-DD`
   - 曾因此把「发现日期+2天」算成 +1 天

3. **findTask/findLog 返回 `{ rec, file }` 结构**，不是记录本身
   - 取值用 `res.rec['字段名']`；曾直接当记录用返回 undefined

4. **服务进程运行期间不要直接 CLI 改 worklog 文件**（并发写会丢记录）
   - 改数据前 `taskkill //F //IM node.exe` 停服务 → 改完 → 重启服务验证

5. **Git Bash `/tmp` 与 Windows node 的 `D:\tmp` 路径不一致**
   - Bash 写 `/tmp/x.json` 后 node 读 `tmp/x.json` 报 ENOENT
   - 临时文件放**工作区内** `tmp/` 目录（两边都能解析），写完即删

6. **改数据后同步刷新三处输出**（避免数据源与汇报不一致）
   - 数据源 `worklog/` → 周报 md → `md-to-docx.js` 出 docx → `generate-dashboard.js` 出仪表盘
   - 改任务状态/日期后，本周报的「进行中/待启动」计数、P1 未闭环数都要核对

7. **跨系统认知勿混**：鼎捷 sMES vs 老MES（玖坤）vs U9 ERP 是三套体系——SQL/数据字典是 sMES，玖坤只涉设备点检表，U9 是发料接口（详见 memory smes-vs-jiukun-system-boundary）
