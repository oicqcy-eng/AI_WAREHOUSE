# evaluation — 评估与质量体系

> **不评估的 Agent 无法迭代。** 本目录定义 **MES实施专家** 的质量评估体系。

## 评估三维度

| 维度 | 含义 | 评估方式 |
|------|------|----------|
| 准确率 | 结论正确 / 符合领域事实 | 标准答案比对 |
| 专业度 | 术语准确、结构严谨、方法正确 | 专家评分（1-5） |
| 稳定性 | 同一问题多次回答一致性 | 重复运行对比 |

## 文件说明

| 文件 | 用途 |
|------|------|
| `test-cases.md` | **测试问题库**（含标准答案与评分要点） |
| `scorecard.md` | 评分记录（每次评估的结果历史） |

## 评估流程

1. **回归**: 每次版本发布/配置变更/Prompt变更后，跑 `test-cases.md`
2. **打分**: 按三维度打分，准确率0/1，专业度1-5，稳定性0/1
3. **记录**: 结果写入 `scorecard.md`，形成历史
4. **门槛**: 综合准确率 ≥ `config/agent.yaml` 的 `min_score`(0.85) 才能发布

## 测试集构成（当前基线）

| 类别 | 题数 | 覆盖 |
|------|:----:|------|
| 知识问答（K） | 3 | 追溯/编码/合规 |
| 场景方案（S） | 2 | 调研/方案生成 |
| 边界防御（B） | 1 | 不编造/承认不确定 |

## 规范

1. 测试集本身要维护：新增业务场景 → 补测试题
2. 标准答案是「评分要点」，非唯一文本——允许不同表达、关键要点命中即算对
3. 评估结果影响发布：不达标 = 不发布、回退优化
