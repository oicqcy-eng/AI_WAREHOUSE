# 厂区报工报表规范（2026-08-14 定版，重庆模式通用化）

> sMES 各厂区「报工查询 → 报表」工作流的通用规范。核心认知：**模板（口径）是资产，报表是「可重跑的视图」**。
> 由重庆报工报表模式（[`delivery/projects/hw-spring-mes/input/c_q_mes/knowledge/重庆查询报表规范.md`](../../../delivery/projects/hw-spring-mes/input/c_q_mes/knowledge/重庆查询报表规范.md)）抽象而来，试点一厂大簧（2026-08-14）。

## 一、分层与文件定位

| 层 | 文件 | 定位 | 维护策略 |
|----|------|------|---------|
| 通用模板（权威） | `今日设备报工查询-SQL.sql`（本目录） | 6 视角参数化（`{{prefix}}`+`{{date}}`），跨厂区一份 | 改口径必记变更日志（见三） |
| 厂区实例（口径卡） | `delivery/projects/hw-spring-mes/input/<厂区>/knowledge/设备口径卡.md` + `sql/`薄说明 | 各厂区自己的设备前缀/工序码/人员口径；**不复制 SQL**，引用通用模板 | 厂区口径变化才更新 |
| 厂区报表（快照） | `delivery/projects/hw-spring-mes/output/<厂区>/YYYY-MM-DD_<厂区>报工数据报表.md`(+docx) | 当日数据视图，可随时重跑再生 | 覆盖规则见二 |

> 重庆为独立 sMES 服务器（`--profile cq`），保留自己独立模板（含按产线拆分视角）；Home 共库厂区（一厂/三厂/二厂/金晟等）用本目录通用模板（`--profile home`）。**两者口径一致、各自分层，不互相复制**。

## 二、报表板块设计（7 节清单，各厂统一）

> ⚠️ **板块可选（2026-08-16 用户决策，替代 8-15 的"必出"）**：以下 7 节是**完整配置（全套）**，但**每次生成报表前必须先向用户展示 7 节清单并询问需要哪几节**，按用户选择输出，**不再默认全 7 节强制必出**——用户明确「不是每次都需要累计总览、按天分布等」。展示 7 节编号 + 常用组合，用户可用编号回复（如"1,3,5,7"）或选组合。历史：8-14 重庆 7 节齐全 ✅；8-15 曾定"7 节必出、不得裁剪"，8-16 改为"先问再选"——**规则以用户最新决策为准**。

1. **元数据头**（3 行自描述 + 来源/模板）：生成时间、数据截止（含进行中 N 次）、口径版本；数据源、查询模板
2. **一、累计总览**：报工记录数/设备数/生产批数/工单数/投入/产出/产出率/时间跨度
3. **二、按天分布**：全量按日报工（近 14 天明细 + 阶段特征）
4. **三、今日报工明细**：设备×生产批×作业站逐条，区分 ✅已完成 / 🔄进行中（ENDTIME 为空）
5. **四、按报工人员统计**：**列集固定 7 列** `工号/姓名/报工次数/生产批/工单/投入/产出`（含 DS=系统管理员代报）——**含产出、工单，任何版式不得裁剪**（2026-08-18 纠正：曾漏产出列）
6. **五、按工单累计汇总**：工单/产品/设备数/投入/产出
7. **六、观察与备注**：产出率缺口、设备接入率、人员口径陷阱、待确认项

> **常用组合速查**：全套 = 1-7；快看版（日常跟线）= 今日总览+今日明细+观察；累计版（阶段/月度汇报）= 累计总览+按天分布+按工单汇总+观察。
>
> **询问方式**：优先用选择卡片给常用组合 + 自定义入口；用户选「自定义」时再逐节勾选（7 节多选）。
>
> **输出方式（2026-08-16 用户决策）**：确认板块后**直接生成 Word（docx）交付**，不在对话内贴全量报表内容——对话只给结果摘要与文件路径，明细进 docx。
>
> **板块列集铁律（2026-08-18 定）**：**含某板块就要带它的全部标准列**——任何版式裁剪只减**板块**不减**列**（尤其 ④人员统计 7 列、③明细 的「投入/产出/时间/状态」、①累计 的「产出率」等）。**③今日明细 无论逐条还是按「设备×工序」聚合，均须同时带「投入+产出」并注明状态**（8-17 曾只带投入被纠正）。生成时以「本节清单 + 最近一份完整报表」为版式基准，不得凭记忆压缩列。
>
> **取数 limit 约定（2026-08-16 用户决策）**：跑数据源查询时按需带足 `--limit`，遇到截断提示（命中 N 行仅显示前 N）就调大——limit 只截显示/导出、不控拉取量，调大纯收益无内存风险。参考：今日明细/人员 ~500；按天/工单 ~200；跨厂区全量/历史导出 ≥6000。query-mes.js 默认已 1000。

> **厂区定制维度**（可选，各厂实例自选）：重庆用「按产线」（EQ-CQSPR/EQ-CQSTB 前缀拆）；一厂大簧用「按设备」。产线划分各厂不同，不强行统一，在实例报表中按需增加一节。定制节是**附加**，叠加在用户选定的板块之上，不替代用户选择。

## 三、报表覆盖规则

- **按日命名**：`YYYY-MM-DD_<厂区>报工数据报表.md`，跨天不覆盖（每天独立文件）
- **当天内可覆盖**：当天多次导出以最后一份为准；历史版本靠 **git 留痕**回溯（`git log -- <报表路径>`）
- 报表是廉价可重跑视图，被覆盖不心疼——数据源头在库，模板可随时重跑同口径

## 四、模板变更流程（铁律）

改 `今日设备报工查询-SQL.sql` 时，**一次改多处**：

1. **模板变更日志**：模板头部「口径变更日志」节记一行（日期 + 改了啥 + 是否口径变更）
2. **受影响厂区实例**：`input/<厂区>/` 的薄说明/口径卡如有引用同步
3. **报表口径注意**：报表头部元数据「口径版本」+ 尾部「口径与注意」更新

> 口径在模板/口径卡/报表各有呈现目的（模板=技术细节、口径卡=速查、报表=解读），**各写各的但必须一起改**，不建第 N 份"字典"文件。

## 五、关键口径速查（通用，2026-08-14）

| 口径 | 定义 |
|------|------|
| 本次投入/产出 | `TBLWIPCONT_EQUIPMENT.InputQty/OutputQty` = `TBLWIPLOTLOG_REPORT.INPUTQTY/GOODQTY+FAILQTY`（**两表逐条一致仅对无分次续报组成立**——2026-08-14 A3 实测一厂 19 行相等/8 行不等，8 行全属分次续报组单行不等、组 SUM 一致；重庆无分次续报全等；**resource.INPUTQTY 是资源加工量，勿用于投入统计**） |
| 报工人员（量=当日） | `TBLWIPCont_Resource.USERNO`（设备表 Creator 为空），姓名映射 `TBLUSRUSERBASIS`；**⑤人员统计量=当天实际报工量**（`TBLWIPCONT_EQUIPMENT` 按 STARTTIME 当天过滤 InputQty/OutputQty，2026-08-14 V2→V3 起不再携带跨日开批累计） |
| 进行中报工 | `TBLWIPLOTLOG_REPORT.ENDTIME IS NULL`，投入为当前累计 |
| 共库厂区限定 | **必须带 prefix**（`LOGGROUPSERIAL∈厂区设备报工组`），否则统计进其他厂区；重庆独立库无此问题 |
| 多人协作 | 同 LOGGROUPSERIAL 多 USERNO，按人各计一次，人员总和 ≈ 当日总量（重复计入故略大） |
| 报工人员去重（2026-08-14 审计） | `TBLWIPCont_Resource.RESCLASS` 0/1/4 三类 USERNO **均为人员工号**（非"1=设备"），同人同组多行；**统计人员必须 `DISTINCT(LOGGROUPSERIAL, USERNO)`，勿按 RESCLASS=0 过滤** |
| 分次续报（2026-08-14 审计） | 同一批同一工序一天内多次进出站（白班/晚班各报一次，共用 LOGGROUPSERIAL）：① 报工记录数=真实进出站次数、SUM 精确=组总量（非膨胀）；③ 明细逐条列 2 行如实反映 |
| 报工次数口径 | ①报工记录数=进出站次数（`COUNT(*)`）；⑤按人员报工次数=报工组数（`COUNT(DISTINCT LOGGROUPSERIAL)`）；分次续报组二者差 1（① 数 2 次进出站、⑤ 数 1 组） |
| 系统代报 | `USERNO='DS'` = 系统管理员代报（2026-08-14 确认），看纯车间报工可排除 |

## 各厂区 prefix 参照

见 [`设备编号前缀-厂区映射.md`](设备编号前缀-厂区映射.md)：一厂大簧=`101-01-DH`、三厂小簧=`X%`（结合设备类别）、二厂=`BM/CP/CQ/...`、金晟=`JS-*`、重庆=`EQ-CQ%`（独立库）。
