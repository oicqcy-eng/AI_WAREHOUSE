## 二、连接配置（凭据不入库）

- 真实配置：`agent/mes-implement-expert/config/db.local.json`（**已 gitignore，含密码，勿提交/勿外传**）
- 模板：`config/db.local.example.json`（只含用户名/服务器，密码位空）
- 重建：复制 example 为 db.local.json，填入两 profile 的 server/port/database/user/**password**；`options.encrypt=false` 为内网直连常规配置
- 密码在用户处或现场；**仓库任何文件都不允许出现密码**（SSMS 运行版故意省略密码）

## 三、运行工具

```bash
node agent/mes-implement-expert/tools/query-mes.js --profile home -q "SELECT TOP 5 * FROM TBLEQPEQUIPMENTBASIS"
node agent/mes-implement-expert/tools/query-mes.js --profile cq  -f tmp/xxx.sql          # 多语句文件（按 --show 逐条显示）
node agent/mes-implement-expert/tools/query-mes.js --profile home -q "..." --out tmp/x.csv  # 导出 CSV（UTF-8 BOM）
```

- **强制只读**：仅允许 `SELECT` 开头的语句，拒绝 `DECLARE`/`INSERT`/`UPDATE`/`DELETE` 等；行数有上限（防误拉全库）
- 权限：账号仅 `db_datareader`（CONNECT+SELECT），无任何写权限
- 时间：库内为**北京时间**（服务器 UTC+8）；过滤当天用 `CONVERT(CHAR(10), 时间字段, 120)='YYYY-MM-DD'`
- 通用查询资产：`data/smes-621-sql/`（本目录）；厂区限定：`delivery/projects/hw-spring-mes/input/<厂区>/sql/`

## 四、断连/异常排查步骤

1. **测连通**：`node agent/mes-implement-expert/tools/query-mes.js --profile home -q "SELECT 1 AS OK"`（cq 同理）
2. **服务器不可达**（超时/拒绝）：检查现场网络/VPN、服务器 1433 端口放行；两库账号各自独立，一个通一个不通属正常
3. **账号失效/密码变更**：找 MES 管理员重置对应只读账号；改 `config/db.local.json` 后重试
4. **库名变更**：当前生产库实际名为 `sMES_Home_Prod`（鼎捷标准命名 `sMES_Production_*` 仅为参考）；若迁移改名，更新 db.local.json 的 database
5. **彻底断连**：改用**离线资产**——主数据查 [设备主数据清单.md](设备主数据清单.md)/[人员主数据清单.md](人员主数据清单.md)/[工序作业站字典.md](工序作业站字典.md)（2026-08-15 快照）+ [设备编号前缀-厂区映射.md](设备编号前缀-厂区映射.md)；流水数据只能由用户从 SSMS 侧导出投喂
6. **重建连库**：重新拉通后，按 [主数据画像总览.md](主数据画像总览.md)「重跑刷新方法」刷新三份主数据快照

## 五、安全约束（铁律）

- 只跑 **SELECT**；只读账号；不用 `sa`/写账号
- **密码不写进任何仓库文件**；db.local.json 已 gitignore，提交前 `git status` 核对
- SSMS 运行版（交付给用户本地执行的 SQL）**不带密码/连接串**
- 断连期间禁止编造数据——查不到就明说查不到，用离线资产兜底
