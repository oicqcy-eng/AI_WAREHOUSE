# PL207 Andon 预警 — 鼎捷 MES V6.1 培训沉淀

> 来源：`raw/PL207_Andon预警模块操作简报.pdf`（58 页，2026-08-24 学习）
> 定位：**车间现场异常快速反应系统**——生产人员遇突发异常无法自行处理时，透过手动安灯（Andon）方式反映给对应处理部门，推动快速处理恢复生产；预警模块则对特定行为/数据指标提前识别风险，通知相关人员提前介入。
> 功能架构：`flows/PL207/PL207_Andon预警模块操作简报_p006_2.png`（四个二级模块）
> Andon=日语「灯/灯笼」音译，源自丰田目视管理：设备/工作站装配呼叫灯，发现问题开灯引起注意，及时处理避免中断。

## 一、模块概述

管理目的：**事前**建立现场 Andon 快速反应机制；**事中**记录处理关键信息；**事后**分析处理过程数据明确改善方向。

四个二级模块（18 功能点）：
1. **Andon 基础数据设置**（9）— 常用语/消息模板/消息分类负责人/消息模板发送设置/消息标签/安灯原因/安灯分类/安灯颜色/安灯对策
2. **消息发送**（2）— 消息发送记录、安灯消息列表
3. **Andon 触发与处理**（3）— 触发安灯、开始处理、完成处理（+确认评价）
4. **看板与报表**（4）— 安灯现况监控看板(SLI01)、安灯日志查询报表(SLI02)、安灯分析报表(SLI03)、安灯处理人分析报表(SLI04)

## 三、作业说明（关键功能点）

### 3.1 Andon 基础数据设置
- **常用语基础数据**：支持搜索/添加/编辑/删除/复制；需【签核】后才可被引用
- **消息模板基础数据**：模板=发送规则载体。重要字段：
  - **驱动**（什么条件下检核是否需要发送）：`时间`（系统背景按循环模式定时检查）/`工单下线`/`开立生产批`/`出站`/`设备稼动`/`模具下模`/`模具叫修`
  - **有值触发**：模板条件查询有数据值即发送消息
  - ⚠️ 系统/客制模板只支持修改；模板识别代号默认带出程序号不可修改
  - ⚠️ 驱动=时间时需**新增一支自动排程作业，工作编号=模板编号**
- **消息分类负责人设置**：维护分类下负责人（接收者）；发送时选分类即发送给对应负责人
  - **执行时间**：消息触发后隔多久发送给此人员（分钟）。例：甲/乙/丙执行时间 1/1/3 分钟 → 触发 1 分钟后发甲、乙，3 分钟后未处理再发丙（**多层级发送**）
  - ⚠️ 目前间隔时间最小 **1 分钟**；间隔<1 分钟需在模板发送资料设定两个任务填不同间隔时间
  - ⚠️ 消息发送是**标准功能**，只发第一人员；逐级发送需配合**安灯模块**且模板设置为【安灯】
  - ⚠️ 人员分类下配多个立即发送（执行时间 0）=无效配置；**接收者分类非人员时**，多个执行时间为 0 的发送人可群发（执行时间 0 只能维护一个人）
- **消息模板发送设置**：选模板+设定自动发送任务。添加→选模板编号→标签/途径/等级/接收者分类/发送分类值/关联作业/安灯等级/安灯分类代号→可改发送内容→【确定】→【核准】（核准后才执行自动发送）。⚠️ 发送设定完成后需**将发送编号回写到消息分类负责人**
  - **途径**：Line、系统、邮件、微信、手环、钉钉（+跑马灯）
  - **接收者分类**：区域、区段、流程、作业站、设备、人员。⚠️ 分类=人员时只发给发送分类值选的人员（无需到分类负责人设定）；其他分类取分类负责人设定人员且需回写发送编号
  - **安灯等级**：`未启用`（只发消息，不显示安灯、只可查看不可处理）／`无记录`（显示安灯，处理只需完成处理）／`需记录`（显示安灯，需先开始处理再完成处理，采集处理时间）。⚠️ 只有无记录/需记录才触发分类负责人多级发送
  - **安灯分类代号**：机台、质量、物料、生产（不包含自定义）。⚠️ 只有系统参数「安灯模组 SlightModule」=1（启用）时，安灯等级/分类代号栏位编辑才有效
  - **关联作业**：收到消息点击直达关联作业
  - ⚠️ 启用安灯（无记录或需记录）+途径=系统+等级=紧急 → 系统生成**跑马灯**
  - **自定义模板**：选自定义模板会出「报表编号」开窗（自定义报表设置中建立，写 SQL 及查询条件）→ 用于客户自定义安灯消息模板
  - **多层级发送**两种方式：①分类负责人执行时间（最小 1 分钟）②模板发送资料设多笔不同间隔（时间不填整数）
  - **发送方式配置**：邮件（SMTP 服务器/SSL/Port 联系客户 IT）；微信（企业微信 ID+授权码，域名+可信 IP=AP 服务器外网 IP）；手环（多嘴猫，本机机器码/通信信道/通信密码）；钉钉（应用秘钥+固定 IP 维护到服务器出口 IP+通讯录手机权限+用户手机号维护）
- **消息标签基础数据**：默认带出 4 个（设备、仓库、公告、质量），多国语翻译
- **安灯原因基础数据**：⚠️ 安灯分类代号（机台/质量/物料/生产/自定义）与模板发送设定对应——安灯消息分类=机台时，完成处理只能选原因类别=机台的原因
- **安灯分类基础数据（MG203，核心配置）**：控制安灯执行流程。属性（线框色=影响业务范围）：
  - **安灯录入信息**（推荐是）：触发时是否需录入信息（步骤[信息录入]，记录更多关联信息）
  - **任务必须接受**（推荐否）：处理人是否需提前接受任务（移动接单模式预留，目前只能选否）
  - **记录开始时间**（推荐是）：处理人到现场确认开始处理（步骤[开始处理]，自动记录处理时长）
  - **安灯复位确认**（推荐否）：处理结束后操作工确认效果并评价（步骤[确认评价]，记录评价得分，拓展功能）
  - **接受处理人一致**（推荐否）/处理人限制（推荐否）：移动接单预留
  - **处理人一致**（推荐是）：开始处理与完成处理是否同一人
  - **复位人员限制**（推荐否）：触发安灯与确认评价是否同一人（拓展）
  - **设备稼动联动**（推荐否）：触发后是否联动设备稼动；`设备状态设定`（推荐故障）→ 触发后稼动调整为配置状态；`处理状态设定`（推荐维修）→ 开始处理后调整为配置状态（可为空）；`设备状态还原`（推荐是）→ 完成处理/确认评价后自动还原
  - **影响层级 1/2/3**（推荐 3）：报警消息至少需通知几级（配合消息模板与调度管理）
- **安灯颜色基础数据（MG204）**：按安灯分类+安灯现况状态（正常/安灯/任务接受/开始处理/待确认）+颜色+是否启用配置；⚠️ 相同分类+状态启用的颜色唯一
- **安灯对策基础数据（MG205）**：与安灯分类对应，完成处理选对策只能选启用且同分类

### 3.2 消息发送
- **消息发送记录**：查询发送情况，异常可重新发送。消息状态：未发送/发送中/发送成功/已经阅读/发送异常
- **安灯消息列表**：收件人查看。4 个入口：生产线/作业人员/作业区工作平台 + 安灯消息

### 3.3 Andon 手动模式（配置与执行）
- **手动模式配置-消息模板基础数据**：新增 **106001/106002/106003** 三个模板用于手动安灯消息推送：
  - ⚠️ 安灯等级选【无记录】；安灯分类代号=机台/生产/物料/质量（操作平台消息中四分类，**目前不支持自定义**）
  - 发送前提：**106001（一级/处理人）**=安灯时长预设范围内+条件符合+消息排程正常执行；**106002（二级/主管）**=安灯时长到达预设+影响层级≥2；**106003（三级/管理层）**=时长到达预设+影响层级=3+二级模板消息已发送
- **操作平台安灯处理过程**：三大作业平台增加 Andon 区域——选中设备→Andon 区域显示该设备各安灯分类状态（按颜色主档配色）；启用的分类均显示；⚠️ 不同状态点安灯分类弹出处理步骤不同（产品配置中心配置也影响）
- **手动模式的执行-触发安灯**：Andon 区域点正常状态按钮→弹出安灯信息录入页→填信息→确认→安灯触发成功（若设备稼动联动则同步调整稼动状态）。字段：设备编号/区域编号默认带出；生产批号=当前设备上所有生产批（今日任务）；作业站编号（锁定会缩小生产批选择范围）；**安灯原因必填**（建议设[其他]原因）；紧急程度（只能安灯监控看板体现，未与消息模板集成）；物料编号=当前设备上机物料
- **开始处理**：扫描用户 IC 卡号或输用户编号→确认（设备稼动联动则同步调整）。⚠️ IC 卡号需用户资料配置否则无法使用；`处理人限制=是`卡控开始处理用户必须在一级响应消息接收者之一（需正确配置执行 106001）
- **完成处理**：IC 卡号+安灯原因+安灯对策→确认（`安灯复位确认=否`则这是最后一步，稼动联动还原此时触发）。`处理人一致=是`卡控开始/完成同一人
- **确认评价**：`安灯复位确认=是`才出现；评分+确认（稼动联动还原挪到此触发）。`复位人员限制=是`卡控安灯人员与最终评价同一人

### 3.4 看板与报表
- **安灯监控查询（SLI01）**：安灯看板雏形，设备维度监控安灯状态，点安灯项看进度（可作后期看板元素）
- **安灯日志查询（SLI02）**：安灯处理历程（开始/结束/确认用户/评分）
- **安灯分析报表（SLI03）**：按次数/时长/原因/对策分析改善方向
- **安灯处理人分析报表（SLI04）**：按处理次数/时长/评分分析处理效率
