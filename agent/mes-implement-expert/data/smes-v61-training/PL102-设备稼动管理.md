# PL102 设备稼动管理 — 鼎捷 MES V6.1 培训沉淀

> 来源：`raw/PL102_设备稼动管理操作简报.pdf`（75 页，2026-08-24 学习）
> 定位：**设备稼动状态全生命周期管控**——设备点检（事前预防）+ 稼动状态切换（事中记录）+ 稼动/点检报表（事后分析），抓取设备每种状态占用时间，改进设备可靠性、设备综合效率 OEE。
> 功能架构：`flows/PL102/PL102_设备稼动管理操作简报_p008_2.png`（四个二级模块）
> 关联：设备建档类作业（供应商/群组/类别/基础数据/群组基础数据）在 **PL101 生产模型配置**详述；设备保养状态联动 **PL201**、故障状态联动 **PL207 Andon**；数采后稼动以数采为准（**PL214 IIoT**）。

## 一、模块概述

管理目的：①**设备点检**——五感/工具/仪器按设定周期对规定部位做预防性周密检查（五定：定点/定法/定标/定期/定人），隐患早发现早处理，防事故降停机 ②**设备稼动**——故障/保养/暂停/设置/关机等稼动状态有效掌握，排除异常稼动提升有效产能 ③**生产信息收集**——出站时收集设备运行信息（运行时间/启停/待机/状态），监控调优生产参数。

四个二级模块（22 功能点）：
1. **设备配置**（8）— 供货商/管理群组/类别/点检表/基础数据/群组基础数据/生产信息/状态原因
2. **区域配置**（1）— 设备群组按类型/摆放位置归类放进区域
3. **设备点检报表**（1）— 设备点检历程查询 Q15
4. **设备稼动报表&调整**（8）— 稼动历程调整、稼动分析日报 R02、稼动明细 R11、稼动日报 R29、稼动统计 R59、MTTR 统计 R07、OEE RA02、点检（B0254/PDA）

## 三、作业说明（关键功能点）

### 3.1 设备配置（八支作业）
- **建档五作业**（供货商/管理群组/类别/基础数据/群组基础数据）：在 PL101 生产模型配置-环境配置中详述，此处不重复
- **设备点检表设置（EQP_QCLIST）**：设定点检项目基础档。支持搜索/添加/编辑/删除/复制；资料需【签核】才可被引用。明细支持【上移/下移】调点检顺序。重要字段：
  - **点检方式**：`区间类型`（录范围，范围内合格）／`ON/OFF 类型`（判断是/否）／`文字类型`（记录结果不判断）
  - **点检时下询**：点检作业时下询设备当前参数值（目前只提供设定）
  - **是否上传图片**：默认否
- **设备点检设定（多频率）**：**点检频率**=`月/周/日/时/班别`；**点检控管**=`不检查`（不做点检不影响进站）／`警告`（不做点检进站警告）／`需有点检记录`（必须做过点检才可进站）／`必须通过点检`（点检结果必须全合格才可进站）
- **设备点检作业（5 个入口）**：作业人员工作平台 / 作业区工作平台 / 生产线工作平台 / 生产线序号收集 / 作业站序号收集
  - 最常用场景：**作业人员/作业区工作平台**在开始加工前做点检
  - ⚠️ **生产线工作平台**：产线及实体设备是否点检对生产批进站**无影响**
  - ⚠️ **生产线序号收集**：建线时自动生成生产线型**虚拟设备**，若在此虚拟设备设点检，生产批进站受卡控
  - ⚠️ **作业站序号收集**：离散型作业站需序号收集时可用此作业，也可做设备点检
  - **PC 端**：单设备点检**可暂存**（下次打开显示暂存信息，按点检频率分别暂存）；**批量点检必须一次性完成不允许暂存**。流程：刷设备编号→自动勾选→【设备点检】带出信息→多频率切换→上传照片（依明细设置）→填各项目结果→保存
  - **手机端（PDA）**：刷编号跳转→传照片→填结果→暂存（可续改）/点检完成
- **设备状态原因基础数据**：原因子类别=**故障/维修/保养/设置/暂停**（分别对应设备各状态）；**故障等级**=管理区分用；**视为有效稼动**=勾选后处于此状态的时间**计入机时**
- **设备类别-原因设定**：添加已签核的稼动原因；**原因同步**（+ / 删除按钮）将原因同步到其他设备
- **设备基础数据-原因设定**：从设备所属类别将稼动原因同步过来
- **设备稼动作业（3 个入口）**：作业人员/作业区/生产线工作平台。**八个稼动状态**：闲置、加工、故障、维修、保养、暂停、设置、关机（各状态设备颜色区分）
  - **状态切换方式**（有向）：`闲置/加工 → 故障 → 维修 → 闲置/加工`；`闲置/加工 → 保养/暂停/设置/关机 → 闲置/加工`
  - 故障切换通常结合安灯预警（PL207）；保养切换结合设备保养（PL201）
  - ⚠️ **作业人员/作业区工作平台**：设备处于故障/维修/保养/暂停/设置/关机时，生产批**无法进出站报工**
  - ⚠️ **生产线工作平台**：稼动状态对生产批**无影响**
  - ⚠️ **设备数采集成后设备稼动以数采为准**
  - 操作：勾选稼动状态→故障/维修/设置/暂停/保养带出原因选框（**故障、维修原因必填**；关机/加工/闲置无需选原因）；不更新状态也可直接更新当前稼动原因
- **设备生产信息基础数据（PRODUCTION_INFO）**：设定设备需收集的生产信息基础档，需【签核】
- **设备基本资料-生产信息收集（产品+设备维度）**：
  - **出站收集**：`出站不需收集`／`出站需收集`（可只收集部分，否则出站卡控）／`出站必须全部收集`（必须全收集，否则出站卡控）
  - **收集方式**：文本／是-否／数值
  - ⚠️ 出站收集设定**针对设备**——同一台设备只能设定一个卡控方式，不是一个生产信息一个卡控
  - ⚠️ 未设定产品类别的情况下，默认出站不需收集
- **生产信息收集作业**：生产批出站时录入设备生产信息

### 3.2 设备点检报表
- **设备点检历程查询（Q15）**：按设备编号+时间查看历史点检记录，提供汇出

### 3.3 设备稼动报表&调整
- **设备稼动历程调整（EQP STATUS ADJUST）**：按条件搜索稼动记录，修改稼动状态和稼动原因
- **设备稼动分析日报表（R02）**：按日汇总各设备稼动历程，算当天稼动率
- **设备稼动明细报表（R11）**：按条件查询稼动历程，算各状态持续时间
- **设备稼动日报表（R29）**：`设备稼动`页签=设备当前状态及已持续时长；`设备生产效率`页签=各项综合参数计算结果
- **设备稼动统计报表（R59）**：按时间区间汇总稼动历程，算稼动率及各状态持续时间
- **设备平均修复时间（MTTR）统计表（R07）**：
  - **MTBF**（平均故障间隔，越大越好）= 总运行时间/总故障次数 = (生产+保养+暂停+关机总时间)/故障发生次数
  - **MTTR**（平均维修耗时，越小维修效率越高）= 总修复时间/总故障次数 = (故障+维修总时间)/故障发生次数
- **设备综合效率 OEE（RA02）**：**OEE = 时间开动率 × 性能开动率 × 良率**（越大越好）
  - **时间开动率** = 设备加工机时/预设产能（描述停工损失）
  - **性能开动率** = 实际加工时间/理论加工时间（评价速度损失）
  - **良率** = 出站良品数/(良品数+不良数)（评价质量损失，含返工品）

## 四、标准 vs 实测差异（自我批判）

| 功能点 | V6.1 标准说明 | 库内实测/现有资产 | 判定 |
|--------|--------------|------------------|:----:|
| 设备基础数据 | 供货商/群组/类别/基础数据/群组基础数据 | `TBLEQPEQUIPMENTBASIS` **747 行**、`TBLEQPEQUIPMENTTYPE` 26、`TBLEQPENGINEERGROUPBASIS` 5、`TBLEQPGROUPBASIS` 74/`TBLEQPGROUPDETAIL` **389 行** → 设备主档/类别/群组真实在建（747 台设备=华纬设备全量口径吻合） | ✅ 已实测（在用） |
| 设备点检 | 点检表设定+点检作业（PC/PDA） | `TBLEQPQCLISTBASIS` **115 行**/`TBLEQPQCLISTDETAIL` **1063 行**（点检表设定）、`TBLWIPEQPQCLISTDETAIL` **265,037 行**/`TBLWIPEQPQCLISTLOG` **30,051 行**（点检执行记录）→ **设备点检在华纬真实大量运行**（26 万+点检明细） | ✅ 已实测（在用） |
| 设备稼动状态 | 8 状态切换+原因必填/可选 | `TBLEQPSTATEBASIS` **8 行**（正好对应 8 稼动状态原因）、`TBLEMSEQUIPMENTSTATE` 734（当前状态）、`TBLEMSEQUIPMENTSTATELOG` **111,260 行**（状态历程）、`TBLEMSEQUIPMENTREASONS` **47,973 行**（原因）→ **设备稼动状态记录 11 万+ 大量在用** | ✅ 已实测（在用） |
| 生产信息收集 | 出站收集产品+设备信息 | `TBLEQPDATACOLLECTION_*` 系列**全 0 行**、`TBLEQPCONSUMEBASIS` 0 → 数采型生产信息收集未启用（华纬设备数采独立于 sMES，见 PL214） | ⚠️ 未启用（数采在外部系统） |
| 设备供应商 | 每台设备需建供货商 | `TBLEQPVENDOR` **0 行** → 供货商基础档未维护（可能由 ERP 同步或不维护） | ⚠️ 未维护（待核） |
| MTTR/OEE 报表 | 稼动分析日报/统计/MTTR/OEE | `TBLEQPMTTRSUMMARY` **0 行** → MTTR 汇总表空（或按需即时计算不落表）；稼动报表权限实际使用待核 | ⚠️ 报表表空待核 |

> 判定：**设备点检（26 万+记录）与设备稼动（11 万+状态历程）是华纬真正在用的核心设备功能**。设备基础主档 747 台吻合。生产信息收集/数采类（DATACOLLECTION 全 0）与 MTTR 汇总表未用——稼动数据人工维护而非数采。设备稼动与安灯联动（PL207）、设备维保（PL201）共用 `TBLEMSEQUIPMENT*` 状态体系。

## 六、待验证/注意

1. `TBLWIPEQPQCLISTDETAIL` 26 万+点检明细对应哪些厂区/设备——三厂小簧报工刚启用，点检是否同步在用（设备口径卡 `input/三厂小簧/knowledge/设备口径卡.md`）
