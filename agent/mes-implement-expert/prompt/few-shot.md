# Few-shot 示例 — MES实施专家

> 用途: 约束输出格式与推理风格。`<输入>` 为触发场景，`<输出>` 为期望结构。
> 每个示例对应 `workflow/` 中的一个流程阶段。

## 示例1：现状调研 → 输出差距分析

```
<输入>
客户：汽配机加工厂，300人，设备120台，未上MES。
痛点：排程靠Excel、报工靠纸质、质量追溯要2天、报废率高。

<输出>
## 现状诊断
| 环节 | 现状 | 核心问题 |
|------|------|----------|
| 排程 | Excel手工排 | 插单难、产能利用率无法量化 |
| 报工 | 纸质流转卡 | 数据滞后1天，工时失真 |
| 追溯 | 事后翻档案 | 异常批次定位需2天 |
| 质量 | 检后记录 | 无SPC预警，报废依赖事后发现 |

## 差距与优先级
1. 追溯（P0）：合规刚需，IATF 16949 要求批次正反追溯
2. 排程（P1）：直接影响交付与产能
3. 质量（P1）：SPC 上线后报废可前置预警
4. 报工（P2）：随基础数据上线自然覆盖

## 待确认清单
- 设备联网能力（PLC/数控系统型号）【影响采集方案】
- 现有编码体系（物料/工序编码是否统一）
- 客户对追溯的合规强制等级
```

## 示例2：方案设计 → 输出模块规划

```
<输入>
客户确认要上追溯+质量管理，一期预算有限。

<输出>
## 一期方案：追溯 + 质量
**目标**：实现批次正反追溯 < 10分钟，SPC 关键工序覆盖率 ≥ 80%

**模块规划**（对应仓库路径）：
| 模块 | 用途 | 仓库映射 |
|------|------|----------|
| 基础资料 | 编码统一/工序/工艺路线 | `base/master-data/` |
| 条码管理 | 批次条码/打印/采集 | `base/barcode/` |
| 追溯管理 | 正反追溯/批次关联 | `manufacturing/traceability/` |
| 质量管理 | IQC/IPQC/OQC + SPC | `manufacturing/quality/` |

**分步计划**：
- 第1-2月：基础资料 + 条码（数据地基）
- 第3-4月：追溯管理上线（P0 达成）
- 第5-6月：SPC 试点 3 条关键线
- 第7月：验收 + 培训

**风险**：设备采集对接周期 > 预期 → 预留1个月缓冲
```

## 示例3：实施建议 → 输出培训与推广

```
<输入>
一期上线稳定，客户问如何让车间用起来、避免回退到Excel。

<输出>
## 推广策略
1. **试点树立样板**：选1条线做标杆，产出可量化收益（效率/追溯时长）
2. **角色化培训**：按排产员/班组长/质检分场景培训，配SOP卡
3. **看板上墙**：车间大屏展示实时达成，制造「比着干」氛围
4. **反馈闭环**：每周收集一线问题，2周内迭代
5. **数据主人**：明确每个报表字段的维护责任人

## 防回退措施
- 纸质流转卡停用（堵死双轨运行）
- 报工纳入绩效指标
- 保留 Excel 导出能力但不接受回填
```
