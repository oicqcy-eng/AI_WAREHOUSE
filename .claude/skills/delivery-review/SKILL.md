# 交付物复核

对 `delivery/projects/<项目>/output/` 中的交付物执行交付前质量复核。
在项目交付前或收到新交付物时使用。

## 复核流程

### 1. 定位交付物
- 确认交付物路径与对应项目
- 列出该项目 output 目录下的所有成品

### 2. 完整性检查
- 逐项对照 `delivery/projects/<项目>/input/requirements/` 需求清单
- P0 需求是否 100% 有交付落点？
- 交付物是否包含：方案说明、分步实施、风险、验收标准？

### 3. 合规检查（脱敏）
- **机器扫描（必跑，勿纯目测）**：`bash skills/delivery-review/scripts/scan-sensitive.sh <交付物路径> [--extra <客户敏感词表>]`——自动扫密钥/token/手机号/邮箱/IP/明文口令等通用敏感模式 + 可选词表（真实客户名/人员名/真实编码，每行一个）
- 命中逐条人工复核（示例 IP/邮箱/代码样例可能是误报），确认真实敏感信息 → 替换为脱敏名（如「客户A」「机加工厂A」）
- 客户端原始数据是否已脱敏/不在库中
- 脚本细节见 [README.md](README.md)

### 4. 质量检查
- 结论先行、论据清晰
- 术语准确（MES/ERP/OEE/SPC 等）
- 量化收益标注假设条件
- 不确定项标注「待核实」，无编造

### 5. 归属与沉淀
- 成品是否在 `output/`（不散落到能力层）
- 是否有可复用经验 → 提炼到 `docs/industry-knowledge/` 或 `skills/`

## 输出复核报告

对每个交付物输出：`✅/⚠️/❌ 清单 + 问题清单 + 修正建议`。
全部通过（无 ❌）才算可交付。
